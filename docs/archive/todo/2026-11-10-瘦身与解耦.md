## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-10 | **不合并那份「精简版」的产物**，只吸收它四个正确决定 | 它砍对了结构、砍错了判断力：勘察字段从 28 砍到 16、交棒能力整个消失、审查门禁归零，还把批量查询改回逐文件（300 文件从 2.3 秒变成 27 秒）。它的四个正确决定是：成熟度分诊、`gaps`/`questions` 结构化、模板零条件、GitHub 原生词汇 |
| 2026-11-10 | 取消 `.project-forge/` 账本，改带内标记 | 痕迹判定的输入必须是**看得见的事实**。账本精确但不可见，用户不知道它存在、删了会退化 |
| 2026-11-10 | 审查方法论（pf-done / pf-review）撤出目标项目模板 | 那是**本仓库的协作纪律**，不是通用规范。让每个用户的每个项目背一套一千行的审查脚本，是把私有偏好当公共服务 |
| 2026-11-10 | 12 个 review flag 全删，答案写进项目 `AGENTS.md` 的「## 取舍」 | flag 是隐藏状态：记不住、看不见、换个人就丢。决定是项目事实，该和项目一起被读 |
| 2026-11-10 | 「单语 README / 没有 CI / 没有贡献指南」从待问降为「可以更好」 | 它们是偏好不是缺陷。把偏好写成缺陷，还债的方式就是加 flag 把它压下去——那正是 flag 地狱的来源 |
| 2026-11-10 | `references/publish-<生态>.md` 四篇合并成一篇速查表 | 那四篇里有大量「什么是 npm」这类科普。**易变的外部事实该写查法而不是快照**，具体字段查官方文档 |
| 2026-11-10 | 删掉 6,955 行测试夹具，只留 27 条行为断言 | 旧夹具在查「中文数字与列表项数对不对得上」「`pf:if` 注释里有没有正文四字词组」。它们的代价是改一句文档就红，换来的防线一条真判据都没换到 |
| 2026-11-10 | 保留 `update.mjs` 与 `zip.mjs` | README 承诺过「下载装的副本会自己保持最新」。撤掉这个承诺要单独决定，不在这次范围 |
| 2026-11-10 | `--strict` 只把「待定」升为拦截，不升「可以更好」 | 「标签还没打」属于后者，而日常提交本来就还没打标签——升上去等于让「还没发版」变成构建失败 |

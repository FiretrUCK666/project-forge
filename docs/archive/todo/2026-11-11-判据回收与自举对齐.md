## 要解决什么

v3.0.0 的瘦身方向是对的（砍注意力税），但砍过了头，留下三类问题：

1. **会写出坏文件的缺陷**：没有命令的项目生成的 `AGENTS.md` 里原样留着 `{{COMMANDS}}`；
   受管区间只刷新「还带 fill 的」，模板新增的区间没有插入路径；手写契约跑 `--upgrade`
   会因为标题措辞不同而重复追加整节。
2. **判据被当废话一起删掉**：worktree 识别、占位署名拦截、凭据处置分流、插件标签前缀、
   Rust 发布超时、Go 标签形状——这些是「做过才知道」的硬判据，不是科普。
3. **自举断裂**：本仓库自己的 `AGENTS.md` 是手写的、不受校验，于是 `templates/` 被砍成
   55 行残废、`compose-agents.mjs` 带着两个 Bug 也没人发现；`.github/` 下的 PR 模板还写着
   已删除的脚本名，`check.yml` 不跑行为断言，`release.yml` 读工作区而不是标签那棵树。

## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-11 | 条件块只在模板里求值，**绝不落进项目文件** | 若留在文件里，`handoff --verify` 会把「还有标记」读成「不干净」，而 `--clean` 又不认识 `if`/`endif`——两层语义越错越远。产物里出现 `if` 现在直接判红 |
| 2026-11-11 | 刷新规则保持「补不覆盖」，漂移交给门禁 | 改成「让受管区间永远等于模板」更省心，代价是冲掉人填进去的内容。判据：区间里没有 `fill` 了，说明有人读过并写过它——那份内容比模板值钱 |
| 2026-11-11 | **不引入**按节名硬编码的「自动刷新区间白名单」 | 那种白名单日后加一节忘了登记就静默失效。刷新改成内容驱动（有没有 `fill`）+ 插入（模板有、文件没有） |
| 2026-11-11 | 恢复 `TEMPLATE_INSTANCES` 的**判据**，不恢复它把私有脚本塞进通用模板的做法 | 同构核对本身是对的（模板改了、实例没跟上就该红），错的是当年把 1,097 行的审查脚本当模板发给用户 |
| 2026-11-11 | 不恢复 `review-record.mjs` 与 `pf-review` 机器围栏 | 那是本仓库的协作纪律，不是通用规范。PR 模板里改成人人读得懂的结构化审查记录 |
| 2026-11-11 | 四篇 `publish-<生态>` 合并成一张 4 卡，三篇 `plugins/<宿主>` 合并成一张 3 卡 | 旧的四篇共 975 行，其中约 92% 是「什么是 npm」这类科普。真要救的是「做过才知道」的那几条，一张卡装得下 |
| 2026-11-11 | `handoff --verify` 从两档退出码改成三档 | 「没查到」与「没有」是两件事。拿 `3` 当干净，等于让一次没做完的检查给不可逆动作背书 |
| 2026-11-11 | 本机路径按「它在哪」分四类，只有 `leak` 报 | 把测试夹具里的假路径报成泄露，修的人第一件事是把那行改掉——而改掉的正好是一份有用的夹具 |
| 2026-11-11 | 预算上调（入口 160→200、参考 1300→2400、全量必读 850→1000） | 新加的每一行都改变了判定。但预算仍是上限不是目标：仅仅因为写得更啰嗦就越界时，改的是文档 |

## 完成后的记录

**这次真正治的是什么**：不是「补回多少行」，是**把「它教别人做」和「它自己做到」变成同一件事**。

v3 的问题不是文档短了，是本仓库自己退出了自己的校验范围——于是模板被砍、脚本带 Bug、
PR 模板里躺着死引用，全都没人发现。这一版把 `AGENTS.md` 交回 `compose-agents.mjs` 生成，
`preflight` 里加了「模板与实例同构」与「纯文档项目渲染无残留」两条自检。自举断了会当场红。

第二件事是**把「AI 不读文档」当成工程问题而不是习惯问题**：入口文件里每个指针都写明
「不读会踩中哪几条判据」，勘察报告的末尾按本次事实生成必读清单。这两处都放在模型注意力
最集中的位置——一处是它必须先读的文件，一处是它正在看的工具输出。

## 要解决什么

独立审查没有约束：每轮都能挑出真的新问题，于是审一轮、改一轮，永远停不下来——历史上出现
过同一件事审了十几轮的情况，每轮指出的问题都成立，加起来却不收敛。

根因不是「审得太严」，是**判据本身没有边界**：审查回答的是「还能不能找出问题」，而那个问题
永远有答案。任何代码都还能再补一处边界处理，任何命名都还能更贴切，所以「做得更好」不能当
完成标准。

同一次梳理还参考了一个面向 GitLab 的成熟项目（它的 issue 流程、打回返工协议、故障注入要求、
worktree 隔离）。值得搬的是**判断机制**，不值得搬的是**记账机制**——那套东西为「多个 Agent
抢同一个 Issue」设计，我们的场景是一个人加 AI，加它只会多一个真相源。

## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-12 | 搬它的**判断机制**，不搬**记账机制**（状态标签、认领标记、P0–P3 严重度、`.issue-flow/` 账本） | 那套东西为「多个 Agent 抢同一个 Issue」设计，它的工具靠平台状态工作。我们的状态由工作记录与 PR 正文表达，再加一套就是第二个真相源 |
| 2026-11-12 | 审查结论**由字段派生**，审查者不宣布「通过」 | 结论一旦靠自然语言声明，机器就只能读字面，而中文否定写法多得数不清。要读懂就得写语言解析器，它迟早读错一条，而读错的方向是把「没过」当成「过了」 |
| 2026-11-12 | 判据只有**动手前冻结的验收标准**，不判「还能不能更好」 | 后者永远有答案，所以它不能当判据。历史上那十几轮，每一轮都在回答后者 |
| 2026-11-12 | 止损设**两条**：同一条标准连续两轮不过 + 轮次超上限 | 只有上限会让「还差一点」被误停；只有单条会让「每轮换个说法」绕过。两条一起，局部精确、整体兜底 |
| 2026-11-12 | **不做**线上问题评测集给审查打分 | 那需要持续的线上漏检数据与长期维护团队，对任意项目不成立。改成：每次真实漏检落一条 `fixtures` 用例，用回归代替打分 |
| 2026-11-12 | worktree **默认不建**，只列三条成立条件，且合并收尾必须卸掉 | 参考项目「worktree 永不删除」，`.git/worktrees` 只增不减、`git worktree list` 慢慢没法读、磁盘上还留着几份完整检出。「先留着以后再说」的以后不会来 |
| 2026-11-12 | 收尾从六步改成**七步**，`worktree remove` 插在 `branch -d` 之前 | 分支只要还被某个 worktree 检出着，`git branch -d` 就拒绝删除，而报错说的是「分支未合并」——两个原因的处理方式完全相反。顺序反了，人就会去用 `-D` 强删 |
| 2026-11-12 | 审查栏从三项扩成**四项**（加「止损记录」），且三处逐字一致 | 前一次的问题正是「模板、实例、判据三处各说各话」——加上字段名常量 + 跨文件对拍，才是把它做成结构约束 |
| 2026-11-12 | 验收标准编号**锚在可勾选那一行**（`^- \[[ xX]\] C\d+`），不按「文里出现过 C1 判」 | 第一版按「出现过」判，实测被模板填写指引里那句「id 用 `C1`、`C2`」撑成了恒真——清单改成 `1.` 也照样绿。这是本次唯一一个被自己的注入用例抓出来的判据缺陷 |
| 2026-11-12 | 注入复验改成**两套门禁都跑**，不按路径前缀猜「该由谁看」 | 第一版按前缀分派，三条注入没红——不是判据不灵，是跑错了那一套。判据只有一条：拆掉一处之后，只要有任何一道门禁报出来，就算有人看着它 |
| 2026-11-12 | 不为外部贡献者建内部工作记录 | 上下文就在 Issue 与 PR 里，那是作者和后来的人都能看到的地方；另建一份内部记录，等于把「为什么这么改」藏进一个他打不开的地方 |
| 2026-11-12 | **改了冻结的 C10**：从「三处逐字一致」改成「三个文件的同一段里各排成一块」 | 独立审查用注入证明原判据是假的：它验的是「这个词在这份文件里出现过」，而 `collaboration.md` 讲那两个字段的正文里本来就有这些词，于是字段块里删掉两行照样绿。判据描述的事实（三处一致）与它实际验的东西（词存在）不是一回事——这不是标准被扩大，是标准写错了，改它要写明，这次写了 |
| 2026-11-12 | 材料清单补进「PR 里前几轮的审查栏」 | 独立审查指出它与「绝不给上一轮结论」冲突：干净上下文不知道这是第几轮、C4 有没有连败两次，止损那条就执行不了。给记录不给结论，「不给上一轮结论」管的是执行者的解释与辩白，不是 `fail: C4` 这个事实 |
| 2026-11-12 | 补两条审查规则：轮次以 PR 里「一轮一行」为唯一计数处；审查中 diff 变了按交付那一刻的 diff 重判 | 这两条都是独立审查在实际走流程时碰到的真实卡点（它中途遇到我改了两次文件），不是假想问题 |

## 一、要解决的问题

### 现状与痛点

`v8` 解决了「判据从查形状到查指称」，但真实外部仓库的多生态接入与全自动自迭代闭环仍存在六类结构性断点：

2. **Skill 枚举写死与自有技能融合断层**：5 个内置技能名称数组硬编码分散在 `scripts/lib/protocol.mjs`（`KIT_SKILLS` / `LIGHTWEIGHT_KIT_SKILLS`）、`kit/skills/lib/cli.mjs`（`KNOWN_KIT_SKILLS`）、`scripts/equip.mjs`、`scripts/compose-agents.mjs`、`scripts/lib/agents-defaults.mjs`、`scripts/lib/survey-reentry.mjs`、`scripts/handoff.mjs`、`scripts/dev/preflight-suite.mjs` 与 `scripts/dev/fixtures-equip.mjs`；`templates/agents-project.md` 意图路由表写死 5 行；且 `survey-reentry.mjs`（`detectKit`）仅扫描隐藏目录读取 `kit.customSkills` 恒返回数组，导致非隐藏 `skills/` 目录下的项目自有技能在 `agents-defaults.mjs`（`customSkillsOf`）中被静默吞掉；旧版已规范仓新增内置技能时无法由 `S1–S4` 自动识别 `upgrade`。
3. **无远端仓工单闭环与切回远端粘滞断裂**：`kit/skills/lib/task-backend.mjs` 中 `LocalOnlyBackend.createIssue` 返回 `{ ok: false, skipped: true, reason: 'local-only' }`，`TASK_BACKEND_METHODS` 缺少 `getIssue`/`listIssues`/`closeIssue`，`flow-inspect.mjs`、`flow-merge.mjs`、`flow-lifecycle.mjs`、`review-ledger.mjs` 与 `govern-state.mjs` 在 `local-only` 下绕过评论/标签/冲突检查与关单；同时无远端仓写入 `.git/pf-local-mode` 后哪怕新增 `origin` 远端并重跑 `S1–S4`，`platform.mjs` 与 `TaskBackend` 仍被 `.git/pf-local-mode` 永久锁死在 `local-only`，且残余本地工单无一键迁移通路。

## 四、关键业务流程

```mermaid
flowchart LR
  S1["S1 只读勘察"] --> B0["基线实跑"]
```

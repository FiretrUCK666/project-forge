## 一、要解决的问题

### 现状与痛点

1. **功能地图扁平化与清洗丢字段**：`docs/feature-map.json` 当前固定为 `version: 1`（`kit/skills/lib/feature-map.mjs` 中 `FEATURE_MAP_VERSION = 1`），22 个 feature 扁平排列，缺少域分组 `domains[]`、依赖拓扑 `dependsOn[]`、角色 `actors[]` 与跨模块端到端流 `flows[]`。`sanitizeFeatureEntry` 按白名单重建对象会静默抹除 `docAnchors[]` 等扩展字段；`kit/skills/dev-verify-tools/scripts/verify-tools.mjs` 在 `handleSync` L163-164 重复调用 `prefillFeatureMapFromRepoMap`；`kit/skills/dev-verify-tools/scripts/verify-tools-audit.mjs` L178（`handleClean`）写死 `{ version: 1, features: cleanedFeatures }` 丢弃根级扩展键；`kit/skills/lib/test-inventory.mjs`（792 行）另立一套 `readFeatureMapSafe` 读写链路且仅余 8 行即触及 800 行硬上限。
2. **上下文注入与流转盲区缺乏拓扑感知**：`kit/skills/lib/context-brief.mjs`、`kit/skills/lib/handoff-package.mjs`、`kit/skills/dev-review/scripts/review-context.mjs` 与 `kit/skills/dev-iterate/scripts/iterate.mjs` 无法沿 `dependsOn[]` 做 1-hop 上下游切片或按 `flows[]` 识别跨模块端到端盲区；无精确路径命中时只截断前 8 个 feature 概览。
3. **缺少零依赖架构全景与活需求视觉投影**：人类无法在单页离线交互视图中直观查看仓库模块边界、角色权责、数据流与待评审方案；`kit/skills/lib/session-state.mjs` 的 Working Brief 存于仓外 `<gitCommonDir>/project-forge-flow/session-state.json`，`kit/skills/dev-plan/scripts/doc-plan.mjs`（796 行）多轮讨论与 `clarify`/`init` 之间缺乏面向人类的实时视觉简报与宿主中立 UI 原型挂载槽。同时，`kit/skills/lib/static-gates.mjs` L84 的 `isUiVisualFile` 尚无签名豁免能力，且全仓 6 处 `UI_VISUAL_EXT_RE` 调用点直接用正则拦截所有 `.html`，会导致确定性派生的 `docs/architecture-map.html` (new) 在普通 PR 中误升为 `high` 风险并强制要求截图实证。

### 目标用户与使用场景

- **项目开发者与规划者**：在 `dev-explore`、`dev-plan`（多轮澄清、方案比选、UI 原型挂载）与 `S1-S4` 接入期获得可读、可缩放、可点击追问的零依赖单文件 HTML 架构图与活需求简报。
- **实施者、审查者与维护者**：在 `contextBrief` 获得低 token 的 v2 分层拓扑切片，依赖写命令自动渲染与只读指纹门禁保证代码、`docs/feature-map.json` 与 `docs/architecture-map.html` (new) 单源一致。

### 产品目标

1. 建立向后兼容的 `feature-map` v2 拓扑层（`domains[]`、`domain`、`dependsOn[]`、`actors[]`、`docAnchors[]`、`flows[]`），并在 `contextBrief`、探索、治理、流转与补测中落地低 token 分层切片与无环拓扑门禁。
2. 落地零第三方依赖的双模视觉投影引擎（`25-60 KB` 自包含 HTML）：仓内确定性派生的 `docs/architecture-map.html` (new) 与仓外实时投影的 Living Visual Brief，实现 Single-Truth Live Projection，无需 AI 每次耗费数万 token 手写 HTML。
3. 统一 6 处 `UI_VISUAL_EXT_RE` 调用点至 `isUiVisualFile`（由 `kit/skills/lib/shared.mjs` 重导出），打通 `S1-S4` 装配体检与 `survey-gap-rules.mjs` 规则对拍，完成 `project-forge` 自身全量 dogfooding 及全链路门禁与真实浏览器验证。

## 二、范围与非目标

### 本次要做（In Scope）

1. **Single-Truth Projection Architecture（单源实时投影与无环依赖架构）**：
   - 仓内架构图 `docs/architecture-map.html` (new) 完全由 `docs/feature-map.json` 确定性派生，首行嵌入 `<!-- @generated by project-forge feature-map-sha256=<sha256> -->` 规范化 SHA256 指纹。写操作入口（`flow-lifecycle-finalize.mjs` `handleFinalize` 在 `git add` 前渲染并暂存、`verify-tools.mjs` `create`/`sync`/`render`、`repo-map.mjs --write-feature-map`）自动渲染同步；只读命令与门禁（`govern-audit.mjs` `reconcile` 保持 `mutating: false`、`flow-lifecycle-hooks.mjs` `verify`、`edit-gate.mjs --final`）保持 100% 只读，发现漂移时由 `reconcile` 提示 `verify-tools.mjs render` 或由 `verify`/`edit-gate --final` 拦截 `BLOCKED_ARCHITECTURE_MAP_DRIFT`（`EXIT.FACT`）。
   - 无环导入 DAG：`kit/skills/lib/feature-map-graph.mjs` (new) 仅依赖 `node:*` 与 `kit/skills/lib/git-core.mjs`（绝不依赖 `static-gates.mjs` 或 `feature-map.mjs`），在其中放置规范化 SHA256 计算与 HTML 首行指纹核验辅助函数，供 `static-gates.mjs` 的 `isUiVisualFile` 直接引用，彻底杜绝 `static-gates.mjs <-> feature-map.mjs` 循环依赖。
   - 仓外 Living Visual Brief 存于 `<gitCommonDir>/project-forge-flow/briefs/<briefKey>.{json,html}` 与 `-prototypes/`，每次渲染直接从 `workRoot`（优先于 `mainRoot`）的 `feature-map.json`、`evaluatePlanNextState`、`indexPlanDocs`、`buildSliceGraph` / `evaluateSliceGraph` 与任务账本现算投影；`confirmedState` 在文档发生编辑后自动置为 `stale`。
2. **Hard Invariants & Budgets（硬不变量与体积预算）**：
   - `scripts/` 与 `kit/` 严格零第三方 npm 依赖（仅 Node 18+ `node:*` 内置模块），零 emoji，不绑定具体 AI 宿主名称或私有路径，不泄露本机 `homedir()` 绝对路径。
   - 全部 `.mjs` 脚本严格 `<= 800` 行（强制将 `test-inventory.mjs` 的 v2 读写迁入 `feature-map.mjs`/`feature-map-graph.mjs` (new) 仅留薄重导出，将 `doc-plan.mjs` 的处理器抽入 `doc-plan-brief.mjs` (new)/`doc-plan-ops.mjs` 使其显著低于 790 行）；`kit/skills/*/SKILL.md` `< 14336 B` 且 `<= 180` 行；`AGENTS.md < 24576 B`（`templates/agents-project.md <= +500 B`）；根 `SKILL.md < 16384 B`（`<= +400 B`）；生成的 HTML 控制在 `25-60 KB`（远低于 `survey-workspace.mjs` 扫描上限与 `scripts/review.mjs` L223-225 的 `secrets.unverified-large` 256 KB 阈值）。

## 四、关键业务流程

1. **拓扑构建与切片投影**：`repo-map.mjs` 与 `verify-tools.mjs` 扫描仓库生成或增量合并 `docs/feature-map.json`（v1/v2 兼容）；`feature-map-graph.mjs` (new) 校验 `domains[]`/`dependsOn[]`/`flows[]` 无环且无悬空引用，计算规范化 SHA256 并向 `context-brief.mjs` / `handoff-package.mjs` / `review-context.mjs` 输出紧凑 L0 域总览 + 1-hop 上下游 + 交集流转。
2. **全景架构图确定性渲染与门禁分离**：`visual-layout.mjs` (new) + `visual-render.mjs` (new) + `architecture-map.mjs` (new) 从 `docs/feature-map.json` 现算生成 `25-60 KB` 自包含 `docs/architecture-map.html` (new)；写操作命令（`flow-lifecycle-finalize.mjs` `handleFinalize` 在 `git add` 前、`verify-tools` `create/sync/render`、`repo-map --write-feature-map`）自动更新它，只读命令（`govern reconcile`、`flow verify`、`edit-gate --final`、`verify-tools render --check`）只检查指纹是否一致；`isUiVisualFile` 对指纹匹配的 `docs/architecture-map.html` (new) 豁免 UI 截图强锁。
3. **活需求简报与原型闭环**：Case 3/4 `note`/`triage`/`doc-locate --topic`（仅显式 `--topic` 时）与 `repo-map --topic` 自动生成仓外 `<gitCommonDir>/project-forge-flow/briefs/<briefKey>.{json,html}`；用户或外部技能产出的 UI 原型通过 `doc-plan.mjs brief --prototype` 挂载进沙盒预览槽（`<= 512 KB` 本地暂存或白名单 URL）；`init` 阶段把 `topicId` 迁移至 `taskId`，`slice --prd` 确定性从 `related_prd` / PRD slug 派生 `parentBriefKey`，后续 `clarify`/`next`/`handoff` 实时重绘并在确认后修改时置 `confirmedState: stale`。

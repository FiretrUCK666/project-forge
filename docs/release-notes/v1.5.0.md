# v1.5.0

## 这一版更新了什么、修复了什么

这一版修的是**判定本身**：一批「看起来在查、其实查错了」的地方，以及几处会让交付门禁
给出反向结论的地方。装法、用法、命令名都没变，更新即生效。

**交棒的结论以前会自相矛盾。** 一个只多了一张图标的干净项目，`--verify` 会返回退出码 3
（判不了），正文却写着「没有发现痕迹」；而报告里那几行盲区提示，任何一个项目都会看到，
看到之后也就没人再看了。现在盲区的判据只有一条——**这一处没扫到，里面可能有痕迹**：
二进制文件不是盲区（文本形态的标记不可能出现在里面），而遍历截断、目录过深、读不出来
这三类补了进去。结论的判决改成先问「能不能判」，再问「干不干净」，所以退出码与正文
不会再打架。

**交棒在自己的源仓库里会报出几百条假痕迹。** 模板里的占位标记、`pf:` 控制标记、写着
本 skill 名字的注释——在它自己的仓库里都是应有状态。现在它会认出「这是我的源仓库」
（判据是入口文件的名字加内核模板逐字相同，不看路径），那些命中改为不计入干净判定；
换个名字的目录照旧严格。

**尖括号占位符的判据换成了「这是不是本 skill 模板里真用过的写法」。** 以前只要长得像就
报，于是 `Array<USER_ID>`、`Vec<ITEM_ID>`、`<BR>` 这些源码泛型全被当成「模板没填完」，
`references/<文件名>.md` 这种文档里的指路写法也算。现在名单由模板里的实际内容反推，
代码文件里只认名单内的词。

**存量项目最危险的一条修掉了。** 生成一次、作者手填一节、再加远端触发重写——那一节会
在账本里变成「本 skill 写的」，交棒时被告知「可以精确撤除」，撤除即是删掉作者写的那段。
现在账本只认**这一次真的由我求值写下去**的节：与本次模板求值结果不逐字相同的，一律
不认领，并主动摘掉旧记录。

**切节不再拆坏代码块。** 文档里展示一段 Markdown 示例（代码块里写着 `## 某个标题`）是
常见写法，按行首切会把它当成真章节，围栏被拆成两半。切节现在走与全仓其余结构判据同一份
围栏扫描，注入与交棒共用同一个实现——两处各写一份时，对「哪里是下一节」迟早给出两种答案。

**生态描述符是真的表驱动了。** 「加一个生态只改一个文件」这句话以前只对一半生态成立：
清单读取只认一个文件名，凡是不用它当清单的宿主（例如用独立清单文件的插件生态）整段事实
静默为空。现在清单按描述符自己声明的文件名读，每个宿主自带「读哪些字段、怎么给人看」。
顺带修好了多包仓库里嵌套通配展开不出子包、Windows 上路径带反斜杠、Windows 上 Gradle 与
Maven 包装器选错那个脚本。

**认证拆成了两条轨道。** 「能推代码」与「能调平台 API」的凭证来源完全不同，以前混成
一句问，于是用 SSH 的项目永远挂在「未确认」上，而且没有任何开关能消掉它。现在：

- 推代码看 `transport`：SSH 远端按「本机配没配过密钥」离线回答，HTTPS 远端问凭据助手
  （并且问的时候带上了仓库路径——少了它，按路径存凭据的机器会答「没有凭据」）；
- 调平台 API 单独看：装了命令行工具没有、登录没有、环境里有没有令牌。三者只要有一条
  通就算齐；本机都没有、但发布跑在持续集成里，也算齐——那种配置用的本来就是仓库里的
  凭据。

**交付门禁不再逼存量项目改自己写好的东西。** 自己写的提案模板没有「回滚点」那一栏时，
降为待问（加一个新开关就能确认沿用原样），不再判成缺；贡献指南里「怎么提交改动」改成
二选一（fork，或同仓拉分支），私有仓库不再被要求写 fork。

**几处会给出错误命令的地方。** 更新脚本剥压缩包前缀时按「最后一个斜杠」切，第一个条目
落在子目录里就会剥掉半截路径，症状是「包里没有 SKILL.md」而包本身完好；Windows 上
Gradle 项目给出的是 `./gradlew build`（该是 `.\gradlew.bat`）；勘察报告里有一行会渲染成
`[object Object]`。

**文档对齐。** 两份 README 里那段「发布页上的源码包」说明以前是错的：它说源码包没有
顶层目录——实际上有，而且是带版本号的目录名；它也确实遵守仓库的导出规则，所以文件集合
与安装包相同。文件表补上了发版规范与 `docs/` 两行。九份超过三百行的章节文件加了同步目录。

**自检多两条。** 一条查「`scripts/lib/` 这个目录行在两份 README 的文件表里」（整块消失
时以前没有任何检查会响），一条量章节体量——**只提示不失败**：不同不等于超标，但一直涨
下去会让人读到一半丢掉上下文。

## 需要你动手的

没有必须做的。两件可选：

- **用 SSH 推代码的项目**：重跑一次交付门禁，那条永远消不掉的「推送认证未确认」现在
  会给出确定答案。想看「通不通」而不只是「配没配」，加 `--probe-network`。
- **本机从没登录过平台命令行工具的项目**：如果发布是交给持续集成的，那条提示现在会
  自动消失；如果不是，`gh auth login` 一次，或配一个令牌。

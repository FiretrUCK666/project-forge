# v3.1.0 — 把判断力找回来，并让仓库自己先做到

这一版修好了四处会**静默给出坏结果**的缺陷，并把被精简掉的工程判据按「只留硬判据、
不留科普」的原则补了回来。**用起来最重要的变化是：生成出的契约不会再带着未替换的占位符，
体检也不再把你自己的测试夹具报成泄露。**

## 改了什么

### 生成的 `AGENTS.md` 不再是模板的空壳

- **修好了一处会写出坏文件的缺陷**：没有声明构建命令的项目，生成的契约里会原样留下
  `{{COMMANDS}}`。它看起来像「这里本来就该有一段命令」，于是没人发现，直到有人照着它
  去找命令。现在这种情况会落一个明确的待填位，让交付体检能拦住。
- **受管区间开始真正跟随项目变化**：项目后来才建远端、才加测试命令、才升级到多包结构时，
  重跑一次就能补上缺的章节，而**你手填过的内容一个字节都不动**。
- **跨模块的重复节不再出现**：手写契约里已经有「构建与测试」时，`--upgrade` 不会再追加
  一份「构建与验证」——同义标题现在认得出来。
- 修掉一处「扫到 `docs/` 里的旧说法就判不干净」的误报：写在代码块里的标记示例不再被当成痕迹。

### 文档骨架恢复成能用的样子

- `templates/agents-project.md` 从 35 行补回 163 行：架构与关键不变量、宿主加载与分发边界、
  版本与回滚四档、发版死锁防护、日常协作的角色判定与五档分流、独立审查与故障注入、
  风险三档、高风险路径。**全部是祈使句与判定表，没有概念科普。**
- 新增 `templates/releasing.md`：项目级发版制度模板（说明写在哪、分哪几节、按什么顺序发、
  发不出去怎么排障）。
- 模板里不再出现指向 `references/` 的指针——目标项目没有那个目录，那种指针必然指空。

### 判据补回来了，但只补硬判据

`references/` 从 1,273 行增到 1,778 行，新增两份按生态组织的硬判据卡：
`publish-ecosystems.md`（Node / Python / Rust / Go）与 `plugin-ecosystems.md`
（Obsidian / VS Code / DSH）。补回来的都是「做过才知道」的那类：worktree 的识别方式、
占位署名未确认前禁推、已推送与未推送凭据的处置分流、插件的标签严禁带 `v` 前缀、
发布轮询超时多半已经成功。

### 写死的地方改成现场探测

- **默认分支名**：不再假定 `main`，从 `origin/HEAD`、当前分支、`init.defaultBranch` 逐级读。
- **发布说明的位置**：`docs/release-notes/<标签>.md` 与根目录 `CHANGELOG.md` 两种模式都支持，
  按项目现状选。
- **标签前缀**：要求裸版本号的生态、或历史标签本来就全是裸数字时，自动取裸版本号。
- **多生态仓库的命令**：前端与后端并存时两套命令都会写进契约。此前只保留一份，结果是
  CI 只测一半，而它看起来完全正常。
- **工作记录目录**：按 `docs/work`、`docs/tasks`、`docs/adr`、`todo`、`work` 顺序探，
  探到哪个用哪个，不搬家。

### 本仓库自己成了这套规范的第一个用户

`AGENTS.md` 现在由 `compose-agents.mjs` 生成并维护，`--check` 会核对标记成对、没有未填占位、
该有的节都在。配套修好了三处「它教别人做、自己没做到」：

- `.github/pull_request_template.md` 里原本写着一个已经不存在的脚本、一个已删除的模板名，
  以及一段没有任何脚本实现的机器围栏。现在它列的是真实命令。
- `.github/workflows/check.yml` 原本没跑行为断言、没跑契约自举、也没有取全历史。
  补上之后，这三类问题在下一次提交就会红。
- `.github/workflows/release.yml` 的版本门禁改成读**标签那棵树里的** `SKILL.md`。
  原来读的是默认分支工作区，补跑旧标签时会拿新分支的版号蒙混过关。

### 勘察报告会直接告诉你下一步读哪一份

`survey.mjs --markdown` 的报告末尾，按本次勘察到的事实生成「下一步必读」：命中插件就点出
插件契约那两节，没有命令就提醒不要按惯例编一条。理由是这一步的注意力全在工具输出上，
把「该读哪一页」放在那里，比写在入口文件的第三屏有用。

## 修了什么

| 现象 | 原因 |
| --- | --- |
| 生成的契约里出现 `{{COMMANDS}}` | 没有命令时既不替换也不落待填位，正好在纯文档项目上触发 |
| 项目后来建了远端，契约里始终没有协作那一节 | 刷新只处理「文件里已经有的区间」，模板新增的区间没有插入路径 |
| 手写契约跑 `--upgrade` 后出现两份「构建」 | 按标题逐字匹配，措辞稍有不同就判成「没有这一节」 |
| 自己项目里的测试夹具被报成「硬编码本机路径」 | 本机路径没有分类，夹具里的假路径与真泄露一视同仁 |
| `handoff --verify` 说「干净」但其实没扫完 | 目录太深、文件太大时静默跳过，把「没查到」说成了「没有」 |
| 能力目录项目的裸版本号标签会被判成对不上 | 标签比对没有归一，`v` 前缀与裸版本被当成两种东西 |

## 需要你做什么

**升级方式不变**：解压覆盖到你所用宿主的用户级 skill 根，目录名保持 `project-forge`。

如果你手上有一份由旧版生成的 `AGENTS.md`，重跑一次会让它补齐缺的章节：

```sh
node "<本 skill 目录>/scripts/compose-agents.mjs" "<项目目录>"
```

它只补缺的和还带待填位的，**填过的内容一个字节不动**。跑完再用交付体检确认一遍：

```sh
node "<本 skill 目录>/scripts/review.mjs" "<项目目录>"
```

**行为变化两处**，都在「更严格」这个方向上：

- `handoff.mjs --verify` 多了第三档退出码 `3`，意思是「这一趟没扫完」。别再把它当成干净
  ——那是一次没做完的检查，不能给不可逆动作背书。
- 交付体检新增两条会拦的项：发布说明里还有没填完的占位、敏感命名的文件超过 256 KB 没扫
  内容。后者报的是「未知」，不是「有凭据」。

## 怎么升级

```sh
# 确认这一版能用
node "<本 skill 目录>/scripts/dev/preflight.mjs"
node "<本 skill 目录>/scripts/dev/fixtures.mjs"
```

## 已知问题

- 旧版往目标项目里留过 `.project-forge/` 账本目录与 `scripts/review-record.mjs` 的，
  `handoff.mjs --scan` 认得出，但**不会自动删**——删除不可逆，得你说一声。
- 勘察的内容扫描有上限（6 层目录、20000 个文件、单文件 256 KB）。超限时报告会明说
  「这一趟没扫全」，但那一部分确实没有被检查过。

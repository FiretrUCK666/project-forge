# v3.1.1 — 独立审查揪出的问题，以及 CI 补抓的两个

这一版没有新能力，只有修复。但**其中两个是会让人丢数据的**：填好的契约会被冲回占位，
以及交棒前的最后一道门会对满是痕迹的项目说「干净」。

## 改了什么

### 填好的内容不会再被冲掉

上一版给「没有命令的项目」在代码块里留了一个待填位。问题在于：判断「这一段填过没有」
的代码**不认代码块**，而读写标记的同一份协议认。两边数出来的数量不一样，后果是
你填完、门禁也绿了，再跑一次生成又把那一节冲回占位。

现在两处用同一份实现，数出来的永远是同一个数。**你删掉那行标记、写上真命令，它就不会再动。**

### 模板改了规则，本仓库自己那份会跟上

`AGENTS.md` 由脚本生成这件事，上一版只做到了「结构对得上」：标记成对、该有的节都在。
内容对不对，没有任何东西在看——模板加一条规则，这里停在旧版，三道门全绿。

现在受管区间里**没有待填位**的那几段，必须与模板渲染结果逐字相同，不同就红。
那几段的正文完全由项目事实推出来（命令、分支名、版本来源），本来就没有人能填的东西，
所以「与模板不同」只可能是一个意思：这份文件落后了。跑一次不带参数就会跟上。

### 交棒前那道门不再说假话

`handoff --verify` 上一版会把**任何**项目的 `references/` 目录跳过——本意是「别把 skill
自己的源码当痕迹」，实现却写成了「路径叫这个名字就跳过」。于是目标项目自己的
`references/` 里有标记也扫不到，`--verify` 返回 0，说干净。

现在判据改成「扫的是不是这个 skill 自己的目录」。目标项目的同名目录照常扫。

### 补进来的新节按模板顺序排

一次补多节时，它们落在文件里的先后是反的。现在按模板顺序。

### 手写契约的节识别不再两头出错

- `## 验证流程`（讲审查流程）不再被当成「构建与验证」；那一节命令现在会真的补进来；
- `## 1. 项目定位` 这种带编号的标题认得出，不会重复追加。

### 同一份代码在两台机器上跑出两个结果

默认分支名会被当成「项目事实」写进契约，而它的取值依赖跑在哪台机器上：`origin/HEAD`
在本地有、浅检出里常常没有；`init.defaultBranch` 开发机设了、CI 上没有。于是同一个项目
在笔记本上生成、在 CI 上校验，会被判成「内容与模板不一致」——**红的那一条与它要证明的事
毫无关系**。

两处一起修：解析链加一道闸门（只有当前分支落在常见默认分支名里才允许拿它当默认分支，
否则 CI 检出特性分支时会把 `release/xxx` 写进契约）；比对时把这类取值整份抹掉，
换台机器跑不再算漂移，而真加了规则照样报。

### 子进程提前退出会把整趟勘察带崩

给子进程写 stdin 时，如果它已经退出，写入会抛 `EPIPE`——而那个错抛在 stream 上、不在
Promise 里，`try` 拦不住。症状是整趟勘察带着栈死掉，报的还是一个与判定毫无关系的错。
现在给它挂了监听：命令的结论由退出码与输出给出，写失败不影响那个结论。

## 修了什么

| 现象 | 原因 |
| --- | --- |
| 填完的构建命令被冲回占位 | 判「填过没有」用了另一套实现，它不认代码块，与读写标记的协议数出两个数 |
| 一次补进来的几节顺序颠倒 | 同一位置逐个插入，后面的把前面的顶到了下面 |
| 手写契约缺了「构建与验证」 | 同义标题用了太泛的词，「验证流程」被当成构建节 |
| 带编号的标题被重复追加一整节 | 同义词匹配没考虑编号前缀；词边界判据在中文后面不成立 |
| 目标项目自带 `references/` 时 `--verify` 说干净 | 跳过规则按路径名写，与「扫的是谁」无关 |
| 模板加规则、本仓库实例没跟上，三道门全绿 | `--check` 只查结构与缺失节，从不比对内容 |
| 同一份代码两台机器跑出两个结果 | 默认分支名的取值依赖跑在哪台机器上，被当成项目事实写进了契约 |
| 勘察偶尔带着栈崩掉，报的错与判定无关 | 子进程提前退出时写 stdin 抛 EPIPE，它抛在 stream 上、`try` 拦不住 |

## 需要你做什么

**升级方式不变**：解压覆盖到你所用宿主的用户级 skill 根，目录名保持 `project-forge`。

**有一条行为变化要留意**：`compose-agents.mjs --check` 现在会比对受管区间的内容。
你如果手改过 `AGENTS.md` 里那些「本该由事实决定」的段落（构建与验证、版本与发布、
日常协作），它会报「与模板不一致」。这不是故障——跑一次不带参数的生成就会跟上，
而你手填的那几段（项目定位、关键不变量、高风险路径）不会被碰。

```sh
node "<本 skill 目录>/scripts/compose-agents.mjs" "<项目目录>"
node "<本 skill 目录>/scripts/compose-agents.mjs" "<项目目录>" --check
```

## 怎么升级

```sh
node "<本 skill 目录>/scripts/update.mjs" --check
```

## 已知问题

- 旧版往目标项目里留过 `.project-forge/` 账本目录与 `scripts/review-record.mjs` 的，
  `handoff.mjs --scan` 认得出，但**不会自动删**——删除不可逆，得你说一声。
- 勘察的内容扫描有上限（6 层目录、20000 个文件、单文件 256 KB）。超限时报告会明说
  「这一趟没扫全」，但那一部分确实没有被检查过。

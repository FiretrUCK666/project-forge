# v4.0.0 — 推送不再等你点头，但发版仍然只由你决定

这一版改的是一件**每天都会碰到**的事：我从「要不要推上去」里退出来。

以前我推分支、开 PR 之前会问你要不要推——理由写的是「对外动作要谨慎」。这个理由站不住：
推自己的分支可以删，开 PR 可以关，两件都撤得回来。真正撤不回来的是合并进 `main`、
发版、改可见性、改写历史。**按能不能撤回分档，而不是按对外不对外**，推分支与开 PR 就回到日常。

同时明确了一件你没说过、我以后也不该自己判断的事：**发版只在你说了之后才做。**

## 需要你做什么

**没有要改的配置，也不用换命令。** 行为变化只在一处：以前我会先问「要不要推」，现在直接推。

如果你是 fork 过来用的，`git pull` 之后就能用上新判据。

## 改了什么

### 推分支与开 PR 不再需要你确认

以前我推之前会问。现在改了分档标准：

| 动作 | 撤得回来吗 | 现在怎么处理 |
| --- | --- | --- |
| 提交 | 能 | 直接做 |
| 推自己的分支、开或改 PR | 能（删分支、关 PR） | **直接做，不再问** |
| 合并进默认分支 | 不能 | 先给你看清单，等你点头 |
| 发版（标签 / 发布页 / 制品库） | 不能 | **只有你说了才做** |
| 改可见性、改写历史 | 不能 | 先给你看清单 |
| 强制推送、改写已推送历史 | 不能 | **永不自动执行** |

这条判据现在写进了 8 份文件（入口、契约、模板、协作参考、中英 README、贡献指南），
`preflight` 会核对它们说的是不是同一件事。以前那句话散在各处，改一处漏一处不会有任何东西报错。

### 发版从「默认动作」里彻底拿掉

「攒了几个改动」「版本号看着该抬了」「上个标签隔得久了」——这些以前在措辞上留了余地，
现在明写不是发版理由。

## 修了什么

### 一处会删掉你文件的问题

`.gitattributes` 里写的是 `/docs/` 这种**目录规则**，git 只排除那个目录里面的东西。
而代码里的判据写成了「名字叫 docs 就算命中」，两者不一致。

后果不只是「包里多了个文件」：自更新脚本照着这条判据**删东西**。一个恰好叫 `docs` 的
普通文件会被当成旧版本残留删掉，报告还写着「顺手清掉了包里不该有的文件」。

现在两边说同一件事：只做前缀匹配，不认裸名。

### 四处「错了也不报」的地方

- 模板里的条件名拼错（`has-cmnds`），以前会被当成「条件为假」整块删掉，不报错、退出码 0，
  产出一份少了整节却看不出任何异常的契约。现在当场报错。
- 形状不对的占位符（`{{release_doc}}`、`{{ PROJECT_NAME }}`）以前既不替换也不报错，
  就那么留在你的 `AGENTS.md` 里。现在渲染完还有残留就报错。
- 交棒遇到读不到的目录、读不到的文件、跳过的符号链接时，以前只记一笔计数，
  结论照样说「干净」。现在一律算「没扫全」，退出码是 3 不是 0。
- 自更新的清理逻辑少了一道前置条件：一旦它被复用到源码副本上，仓库自带的工作记录目录
  与自用脚本目录会被整棵删掉。现在先确认「这不是源码副本」才允许删。

### 命令不再按生态惯例编

以前没有测试文件的项目也会被给一条 `pytest`，没有 `gradlew` 的项目也会被给 `./gradlew`。
这些命令在 CI 里必挂，而那条失败看起来像「代码坏了」。

现在只按项目里**真实存在的文件**给命令。没有测试证据就不给测试命令，直接说「本项目无构建与测试步骤」。

## 兼容性

- 最低运行环境不变：Node 18（这一版在 18 与 22 上都跑过 CI）。
- **`handoff.mjs --verify` 新增了一个退出码 `4`**，表示「这一趟不适用」（目标是这套 skill 自己的源码仓库）。
  以前这种情形给的是 0。如果你的脚本按退出码分支，需要多认一档。四档含义：
  `0` 干净 / `1` 有痕迹 / `3` 没扫全 / `4` 不适用。
- `isRepoOnlyPath('docs')` 的返回值从 `true` 变成了 `false`——这是修正，与 git 的语义对齐。

## 怎么升级

解压覆盖到你所用宿主的用户级 skill 根，目录名保持 `project-forge`。覆盖之后跑一条自带的检查：

```sh
node "<本 skill 目录>/scripts/update.mjs" --check
```

它只检查、不写盘。输出里会告诉你这份副本现在是不是最新版。

## 目标与验收

一次查清「这个 skill 自己有没有坏的地方、有没有漂移、有没有把该交给配置的东西写死」，
而不是逐处打补丁。可验证的验收：

1. **判对**：`--fast` 与完整模式对同一事实给同一个答案；`review` 不会把编码损坏读成手写文件；
   `--check` 不再删文件；不在不存在的路径上造账本。
2. **一个生态名都不留在主引擎里**：`survey.mjs` / `review.mjs` / `compose-agents.mjs` / `render.mjs`
   里搜不到具体生态名；加一个生态只改 `ecosystems.mjs`。
3. **入口有预算门禁**：`SKILL.md` 超过上限即红。
4. **文档只有一处权威**：同一件判定不在入口与 reference 各写一份；数量自称不写没人核的数字。
5. **没有「要人记得改」的清单**：文件地图、包边界、生态判定都靠结构规则，不靠登记表。

## 做了什么

### 一、判定错误（实测确认后修复）

| 编号 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| B1 | `--fast` 说没有 git，完整模式说有 | `runCapture` 不返回 `error`，`error?.code !== 'ENOENT'` 恒真 | 补 `error` 字段 |
| B2 | 网络探测读的是 `undefined` 根 | `info.root` 从未被赋值（`detectGit` 用的是 `workTreeRoot`） | 引入 `reachableRoot` |
| B3 | UTF-16 的 `AGENTS.md` 被当成手写文件放行 | 读失败被读成「文件不存在」 | 读失败单独成一档，并明确劝阻 `--handwritten-agents` |
| B8 | `--fast` 的内容扫描字段只有 2 个，markdown 打印 `undefined` | 两种模式各拼一份形状 | 单一构造器 `buildContentScan` |
| B9 | `--json --markdown` 静默选一个 | 没做互斥 | 互斥，退出码 2 |
| B10 | `-x` 被当成目录名，抛裸栈 | 参数按前缀过滤写错 | 只认 `-` 开头的开关 |
| B4 | `--check` / `--status` 会删临时文件 | 只读模式也走清理 | `clearStaleTemps(path, { dryRun })` |
| B5 | `--record .` 抛 EISDIR 裸栈 | 没判它是不是文件 | 提前判，报人话 |
| B6 | `--remember` 在不存在路径上造目录 | 写操作没判目录在不在 | 明确拒绝 |
| B7 | 账本读不出来时静默重建，抹掉已有记录 | 写侧把 `unreadable` 当 `absent` | 写侧拒绝并报路径 |
| B11 | 全量模式下「不是 git 仓库」不报 | 条件多写了 `scope !== undefined` | 去掉那个条件 |
| B12 | `render.mjs` 的 `s.host?.id === 'dsh'` 是死条件 | 描述符的 id 不是 `dsh` | 按 kind 判 |
| B13 | GitHub 接口地址常量在 `update.mjs` 与 `release-notes.mjs` 各写一份 | 两处各写一遍 | 收进 `lib/protocol.mjs` 的 `apiBase` / `apiTarget` |

### 二、取消「要人记得改」的清单

- **文件地图的逐文件登记表**整块删掉（`SKILL.md` 与 `AGENTS.md` 两处），改成「按情境读哪一份」
  的查表 + 结构说明。连带删掉 `lib/text.mjs` 的 `readFileMap` / `readFileMapSection`。
- **包边界**改成结构规则：`.gitattributes` 的 `export-ignore`（文本形态）与
  `lib/protocol.mjs` 的 `REPO_ONLY_DIRS` / `REPO_ONLY_FILES`（代码形态），`preflight` 核对两处一致，
  包集合候选来自**真跑一次的 `git archive`**。
- **可达性判据**替代登记表：每个 `references/`、`templates/` 文件与每个随包脚本，
  都要被别的文档提到或被别的脚本调用过——「写了却没人指得到，等于没写」。
- `update.mjs` 不再按「包里的表」删文件：授权来自结构规则；旧版遗留的文件**只报不删**
  （分不清是遗留还是使用者自己的东西，选那个不会造成损失的做法）。

### 三、入口（`SKILL.md`）与项目契约（`AGENTS.md`）

- 加**默认范围**规则：什么都不说 = 全量配齐并融合进已有项目；点名了 = 只做那几件。
- 加 `SKILL_MAX_BYTES = 30 KB` 门禁（含 2 KB 余量告警），`SKILL.md` 现 29612 字节。
- 入口收成指针：文件地图只留「AI 会跑到的那几条命令」；硬不变量 11 与硬门控表去掉复述，
  判据一律指向 `references/`；G7 的「只有用户能定的事」清单只在 `docs-set.md` 一处。
- `AGENTS.md` 从 51492 压到 44175 字节（上限 49152）。

### 四、生态名离开主引擎

- `survey.mjs` 的 `detectEcosystem` 不再认任何具体生态：宿主类由 `detectHosts(HOST_ECOSYSTEMS, ctx)`
  判，依据那行文字由描述符的 `evidenceFor` 给。
- `review.mjs` 的生态专属门禁搬进描述符 `checks(s)`（DSH 的发布范围/补丁/三态/发现载体，
  Obsidian 的 id 形状/附件/versions.json/触发器形状），`ecosystemChecks` 只负责并进总账。
- `compose-agents.mjs` 的模板条件由描述符 `conditions(s)` 提供。
- `render.mjs` 的插件专章引用按描述符的 `chapter` 拼出。
- `compose-agents.mjs` 的「兼容范围 vs 专章核对版本」提示不再写死 DSH，任何带专章的生态都生效；
  Obsidian 的宿主依赖声明在 `package.json` 而身份在 `manifest.json`，由描述符的
  `depsManifest` 声明，`hostRuntime` 按它读。

### 六、其它

## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-08 | 生态专属检查做成描述符的 `checks(facts)` / `conditions(s)` 字段，不另建插件注册表 | 描述符已经是这个项目的既有扩展点；能并进现成的就不另起炉灶 |
| 2026-11-08 | 放弃「让 `templates/ci-release.yml` 调本 skill 的 `release-notes.mjs`」 | 那会把目标项目的发版链绑到本 skill 的脚本上，交棒之后就断。改成工作流里直接查那两条结构判据 |
| 2026-11-08 | 放弃「给中档风险加机器判据」 | 风险档与状态是意图不是事实，机器判它就会有人改文字过门禁 |
| 2026-11-08 | 保留 `update.mjs` 的 GitHub-only 判定 | 这个 skill 只服务 GitHub 是既定事实，不是缺陷 |
| 2026-11-08 | 旧版遗留文件改成**只报不删** | 包里只说得出「我现在有什么」，分不清「旧版遗留」与「使用者自己的笔记」，选那个不会造成损失的做法 |

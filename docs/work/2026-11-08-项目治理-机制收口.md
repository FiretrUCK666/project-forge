## 目标与验收

一次解决「同一个机制在好几处、彼此还打架」这一类问题，而不是逐处打补丁。四项可验证的验收：

1. **发版规范不再是固定两节**：模板给出「一节必需 + 按需的节」，并写明「项目选定的那几节
   写进自己的规范」；`SKILL.md` 的 G7 与它不再矛盾。
2. **日常协作只有一个落点**：目标项目的 `AGENTS.md` 里，日常改动、工作记录、审查、合并收尾
   都在新增的 `## 改动怎么落地` 一节里，`## 版本管理（必守）` 不再夹带协作流程。
3. **审查子代理的派发被写清**：新上下文、不给执行者的思路、不给上一轮结论、默认只读、
   下一轮重新派、主 Agent 不能自己充当审查——参考文档、模板、本仓库契约三处一致。
4. **存量项目接得上**：`--upgrade` 能把新的一级节补进一份手写 `AGENTS.md`，而原有节一个
   字节不变。用 fixture 实测，不靠推断。

## 计划

4. 参考层：`collaboration.md` 增「怎么派」「放哪、叫什么」，`docs-set.md` 补结构表与

## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-08 | 把协作流程拆成新的一级节 `## 改动怎么落地`，而不是继续留在 `## 版本管理` 里 | `--upgrade` 会给升级前就存在的节打 `pf:keep`，此后整节不刷新；留在里面意味着存量项目永远拿不到，且缺节判据看不见小节 |
| 2026-11-08 | 发版说明改成「一节必需 + 按需的节」，删掉「顺序固定，只写这两节」 | 原写法与 `SKILL.md` G7「分几节由项目定、要问用户」直接矛盾，AI 照哪一份都对不上 |
| 2026-11-08 | 「需要你动手的」从固定节降为可选节，本仓库改叫「要怎么跟着升级」 | 纯文档、插件、skill 的很多版本根本没有「使用者必须动手」的事；固定它只会逼出空节或编造内容 |
| 2026-11-08 | 放弃：让机器校验「发版说明分了哪几节」 | 那正是要交还给项目的决定。只校验任何项目都成立的那几条（有标题、标题同号、无空节、无同名节、无骨架标记） |
| 2026-11-08 | 放弃：为问题（issue）建 `docs/issues/` 目录 | 问题原文在平台上，复制一份进仓库必然漂移；关联靠工作记录里写编号 |
| 2026-11-08 | 工作记录文件名不写日期、不写编号（已取代：见下一条） | 当时的顾虑是按主题找、不按时间找；这条被推翻，因为「什么时候开始的」也是读者要的事实 |
| 2026-11-08 | 改成 `YYYY-MM-DD-主题.md`：日期在最前、建单日之后不改；仍不写编号与状态 | 日期是唯一不会变的东西，所以不会带来改名；文件系统时间不可靠（克隆/复制/检出都会重置），平台时间只覆盖平台上的东西。状态会变、编号会重排，所以那两样仍不进文件名 |
| 2026-11-08 | 放弃：把「派子代理」做成脚本或命令 | 它依赖宿主能力（子代理/新会话），脚本无法跨宿主统一；写成协议，由执行者按当前宿主实现 |
| 2026-11-08 | 历史发布说明一个字不改 | 它们是快照，按当时的规范写；改它们等于篡改历史，也会让 lint 的容差被迫为新规范让路 |
| 2026-11-08 | `references/remote-github.md` 压到 602 行（原 670），仍略超 600 行软预算 | 剩下的都是判据；再压就要删依据。软预算的说明本身就写着「压不下来就留着」 |

## 断点

第一轮独立审查（新上下文、只给材料清单）报回 4 条阻塞、6 条建议，已修：行动导航的协作判据
随节名失效、发版节第 1 步指向不存在的文件、发版规范模板承诺了目标项目并不存在的结构检查、
三套叫法（工作记录 / 任务单 / 工作项）。

第二轮独立审查（同样新上下文）又报 4 条阻塞、6 条建议，全部是「修法本身还有洞」，已修：

- 「抬版本号 / 重新构建」被挪到了只判远端的条件里 → 不发布的远端项目会一边说「不对外发布」
  一边说「改一个字都要抬」。已加回发布与角色两道条件。
- 审查材料表一边给「提案评论」一边说「不给上一轮结论」→ 评论正是结论的落点。改成只给正文，
  并把贡献指南与发版规范补进「给它」那一列（与参考文档的读书单同源）。
- 发版规范路径写死 `RELEASING.md`，而勘察已认五个候选 → 改成 `{{RELEASE_SPEC_FILE}}`，
  由勘察给值；规范在 `docs/` 下时也不会指空。
- 标题只按空白切第一个词 → `# v1.6.0：修好导出缺页`、`# v1.6.0（首个公开版）` 被误判错号；
  整份说明被注释包住时反而放行。改成「取标题里第一个像版本号的东西」+ 结构判据跑在去掉
  注释后的文本上。
- 顺带：`--check` 补了三条断言（通过 / 缺节 / 错号），自检恢复「标题与文件名同号」比对，
  默认节名统一成「要怎么跟着升级」，fork 不再渲染版本号与发版那几节。

**下一轮**：等第三轮独立审查（新上下文、对冻结的 HEAD），通过后合并、关本单、六步收尾。

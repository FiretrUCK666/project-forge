## 要解决什么

这套协作规范有三处结构性缺陷，单纯放开量写规则只会越写越漂：

1. **同一条规则抄在四到六处**——「3 轮全量 + 2 轮增量」在 4 个文件、分档表在 4 处、收尾七步在 3 处、收敛规则在 6 处。每多一份副本就多一处会漂。
2. **指针绑在会动的东西上**——全仓库 14 处 `第N节` 形式指路，`collaboration.md` 一重排全部指错且不报错。
3. **勘察说完体检不认**——`survey` 与 `review.mjs` 是两套独立判断，中间没有桥；勘察报的缺口体检可能完全没提，没有任何东西会发现。

外加两处：

4. **生成之后就没人复核**——`AGENTS.md` 里的默认分支、点名的脚本路径一旦渲染进去就是死文字，项目变了契约仍写旧值，没有门禁看得见。
5. **工作记录是平的**——装不下「谁在执行、工作位在哪、这是第几轮」，这些只能靠会话记忆，跨会话就没了。

不做会怎样：每加一条规则就多一处副本，六个月后两份文档各说一套，而照着旧那份做的人不会收到任何报错。

## 决策与放弃的方案

| 时间 | 选了什么或放弃了什么 | 为什么 |
| --- | --- | --- |
| 2026-11-12 | 放弃：把 `collaboration.md` 拆成 `collaboration.md` + `review.md` 两份 | 拆开会多出一处「同一件事该写哪份」的判断，而两份之间又会互指。改为同一份内部按相位分区，指针一律用标题名——治的是「指针绑在节号上」这个根，不是文件数量 |
| 2026-11-12 | 放弃：状态标签体系（`status::*`）、本地状态账本、多执行者竞态仲裁 | 一个人类加一个 AI，那些机制会变成第二份真相源，迟早与平台对不上。并发用「一次一件事」这条判断回避 |
| 2026-11-12 | 选：缺口用稳定 id 而不是散文比对 | 散文措辞一改对拍就失效；id 是判据，措辞是排版 |
| 2026-11-12 | 放弃：勘察缺口在运行时由 `review` 反查 | 那要求 `review` 每次都重算勘察全量。改为**静态核对两侧名单**：新增缺口必须同时登记处置，否则门禁红。成本在改代码那一刻，不在每次运行 |
| 2026-11-12 | 放弃：`SKILL.md` 拆成两份入口 | 宿主只认一个入口文件；拆开等于多一处可能不同步的地方 |
| 2026-11-13 | 选：契约回查按**形状**判（反引号里的仓库内路径、代码块里的分支名），不按七类逐项清单 | 逐项清单每加一种契约就要加一段代码，漏掉的那段不会有人发现。形状判据覆盖「项目变了而契约没变」这一整类，新增契约只要写成路径或分支就自动被覆盖 |
| 2026-11-13 | 放弃：判「契约里的命令还能不能跑」 | 一条写对的命令与一条写错的命令在文本上长得一样，要判就得真的执行它，而交付体检不该跑用户项目的构建。那一层归项目自己的门禁 |
| 2026-11-13 | 改：合并授权从「四档、外部 PR 与人合」改为「审查通过即由审查者合，只有弱化门禁要人点头」 | 人是不会去读代码的，把合并挂到人身上只增加等待、不增加判断。真正做判断的是审查（冻结标准 + diff + 门禁输出 + 故障注入）。**弱化门禁是唯一例外**：别的改动做错了下一次门禁会红，它做错了以后每一次都不会红，而外观是「构建绿了」 |
| 2026-11-13 | 选：锚点比对用**前缀匹配 + 唯一性**，不用逐字相同 | 逐字相同会把标题锁死（改一个副标题就红），最后一定会被加例外表绕过去；同前缀多命中时判红，于是「写得短」与「指得准」同时成立 |
| 2026-11-13 | 改：`git archive` 那条命令写成先落 tar 文件再列目录 | 管道版在 Windows 上被 shell 转码破坏，`tar` 报 `Damaged tar archive` 并重试上千次；落文件版两边都对 |
| 2026-11-13 | 改：`gap-coverage` 的切块从「按两空格缩进」改成「按 `id:` 行」 | 缩进是排版，不是判据。按缩进切时，换一次格式化器就让 17 条缺口全部静默消失而退出码仍是 0——判据被削成恒真 |
| 2026-11-13 | 加：`gap-coverage` 用登记的 id 名单做双向比对 | 只判「读出来的都配好了」时，读出来是空数组也全过。补上「登记了却没读出来」与「读出来了却没登记」两类，空解析立刻变成 17 条红 |
| 2026-11-13 | 改：`claims.mjs` 的分支正则只收普通分支名，`-b` / `-c` / `-C` / `--detach` 一律不收 | `git checkout -b feat/x main` 是流程说明，不是「主干叫什么」的承诺。把它当承诺，每个文档化分支流程的项目都会收到假警报，而假警报一多这条判据就会被关掉 |
| 2026-11-13 | 改：`checkEntry` 在 worktree 检出里不判「目录名必须等于 name」 | 审查位是 `.worktrees/review-<短SHA>/`，目录名是隔离用的临时名字，不是安装位置。判红会让每个审查者先撞一次假故障；改用结构事实（`.git` 是文件）来分辨 |
| 2026-11-13 | 改：推送分档的文件清单拆成「日常流程」与「提单模板」两组，后一组只查与作者有关的两条说法 | 两份提案模板会落进用户项目，必须讲清「谁能合」；但「能不能撤回」「推分支属日常」是实现流程，塞进模板只让人多读无关的一段 |

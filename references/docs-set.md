# 文档套装

## 何时读本文件

要写或改项目文档时读：`AGENTS.md`、`README`、`CONTRIBUTING`、`LICENSE`、`RELEASING`，
以及 `.github/` 下的 Issue 与 PR 模板。

---

## 一、读者是谁，决定怎么写

| 文档 | 读者 | 怎么写 |
| --- | --- | --- |
| `AGENTS.md` | **AI**，每次会话自动读 | 写机制、边界、命令。要具体值时写「从哪里取」 |
| `README` | **人**，可能第一次听说这个项目 | 可直接复制的命令与地址。第一屏说清「这是什么、怎么跑起来」 |
| `CONTRIBUTING` | **外部贡献者** | 怎么装环境、怎么跑门禁、怎么提 PR |
| `LICENSE` | **法律意义上的使用者** | 逐字用 SPDX 标准文本，只换年份与版权持有人 |
| `RELEASING` | **要发版的人** | 说明放在哪、分哪几节、按什么顺序发 |

这条区分决定一切：AI 那份要「从哪里取」因为它会推理，人那份要「现成命令」因为他要照做。

### 「永不覆盖」对散文文件是什么意思

**先读，再判断，只补缺的**：已有的章节不重写（觉得不好可以在汇报里说，不要直接改）；
缺的插在合适位置，保持原有标题层级与语气；已有的语言跟着走；已有的格式跟着走。
只有用户明确说「重写」时才整篇替换。

### 用户不可达时怎么办

被委派的子代理、无人值守运行都会遇到。判据：**问不到人不能成为停顿的理由，也不能成为
自作主张的借口。** 用安全默认值推进，把决定权留清楚：

| 决定 | 安全默认 |
| --- | --- |
| 可见性 | 私有 |
| 许可证 | **不落**（编一个许可证是替人做法律决定） |
| 收不收外部贡献 | 不落协作模板 |
| 要不要 CI | 落，但只跑项目已有的命令 |
| 署名 | 从环境读，读不到就留着缺并说明 |

推进完之后在汇报里单独列一段「等你回来的三件事」，不要混在正文里。

### 只有用户能定的那几件事

集中一次问完，不要分几次打断。这几件脚本推不出来，也都只在写文档时才需要：

| 事 | 为什么不能替你定 | 要不到时 |
| --- | --- | --- |
| 许可证 | 法律决定 | 不落，记成待定 |
| 署名来源 | 决定提交记在谁名下 | 从环境读，读不到就留缺 |
| 可见性 | 公开不可撤销 | 私有 |
| 账号或组织 | 决定推到哪儿 | 当前登录的账号 |
| 收不收外部贡献 | 决定要不要落协作模板 | 不收 |
| 要不要自动发版 | 涉及仓库权限与凭据 | 不配 |
| 发版说明分几节 | 读者关心的事因项目而异 | 用模板的默认菜单 |

**写法**：一次列出，每项给你的建议，然后等他答。

---

## 二、必须的只有两件

| 文件 | 必须吗 | 什么时候落 | 骨架 |
| --- | --- | --- | --- |
| `README.md` | **是** | 一直 | `templates/readme.md` |
| `AGENTS.md` | **是** | 一直 | 由 `compose-agents.mjs` 从 `templates/agents-project.md` 生成 |
| `LICENSE` | 看情况 | 公开项目、可发布项目 | `templates/license-<类型>.txt` |
| `CONTRIBUTING.md` | 看情况 | 要收外部贡献 | `templates/contributing.md` |
| `RELEASING.md` | 看情况 | 要发版 | `templates/release-notes.md` 给的是说明的默认菜单 |
| Issue 模板 | 看情况 | 要收外部报告 | `templates/issue-bug-report.md`、`templates/issue-feature-request.md` |
| PR 模板 | 看情况 | 要收外部改动 | `templates/pull-request-template.md` |
| 工作记录 | 看情况 | 要跨会话 | `templates/work-item.md` |
| CI 流水线 | 看情况 | 要持续集成 | `templates/ci-check.yml`、`templates/ci-release.yml` |

**少一件不是缺陷。** 单语项目不需要翻译，个人项目不需要贡献指南，不发布的项目不需要
发版规范。把偏好写成缺口，会让每个项目都欠一笔还不完的债。

---

## 三、`AGENTS.md`

### 它是项目契约，不是作者笔记

判断标准：**换一个人接手，这份文件还成立吗？**

| 能写 | 不能写 |
| --- | --- |
| 机制、边界、不变量、硬性规范 | 某个账号的用户名、邮箱 |
| 构建 / 测试 / 发布该做什么、按什么顺序 | 推送目标、发布目标这些**取值** |
| 为什么这样要求 | 一次性的版本号、日期、某人当时的决定 |

### 已经有的怎么办

| 现状 | 动作 |
| --- | --- |
| 不存在 | 生成一份，用勘察事实填能填的部分 |
| 有 `project-forge: begin` 标记 | 刷新还带占位的区间，标记之外不动 |
| 存在但没有标记 | **不动**。它可能是手写的，而手写的往往更贴合项目 |

第三种最容易做错：用户手写的契约里可能有一句「这个项目的 X 永远不许改」，那是他从事故里
学来的——自动生成的东西不会知道。要补的话用 `--upgrade`：只**追加**缺的节，每节带自己的
标记，已有的字一个不动。

### 生成之后必须做的一件事

填掉所有 `project-forge: fill` 占位。填法是**读代码**，不是猜。填完把那一整行标记删掉——
**留着它，看起来就像「这里已经填过了」**。一份带空占位的契约比没有契约更糟。

`review.mjs` 会把未填的占位报成 `[缺]`，这是唯一一个「不填就过不了」的文档项。

### 预算

`AGENTS.md` 每次会话都被注入上下文，所以它**按行付费**。判据：只写「不知道就会改坏」
的东西；机制细节指向代码或别的文档，不复述；不写面向终端用户的科普。

超长时优先删三类：历史沿革、被否决的方案、当前版本的快照值。

### 「## 取舍」节

由维护者写，脚本不碰。它是「只有使用者能定的事」的记录处：

```
- `license`：不放，因为这是个人项目
- `no-ci`：不配，本地跑就够了
```

`review.mjs` 会把记下的项当作已表态，不再报 `[待定]`。**决定写在项目里**，不藏在 flag
或隐藏文件里——它是项目事实，该和项目一起被读、被争论、被接手。

## 四、`README`

第一屏要回答三件事：**这是什么**（一句话，不要形容词堆砌）、**为什么用它**（具体的
问题，不要说「强大」「优雅」）、**怎么跑起来**（一条能复制的命令）。

| 判据 | 反面 |
| --- | --- |
| 每条命令能直接复制执行 | 写 `<你的路径>` 却不说是什么路径 |
| 环境要求来自清单声明 | 凭印象写「需要 Node 18」而清单写着 20 |
| 不承诺没做出来的东西 | 还没发布就写 `npm install <包名>` |
| 示例是最小可运行 | 贴一个需要先配五个环境变量的例子 |

**已有的 README 不符合规范时**：补缺的节，不改已有的表述。能在原有结构里补，就不要重排。

**双语 README**：只有项目原本就是双语、或用户主动要求时才加。单语项目硬加一份翻译，
得到的是一份会过期的翻译和一份永远要两边改的负担。

---

## 五、`CONTRIBUTING`

要收外部贡献时才落。三块：怎么装环境、怎么跑门禁（命令与 `AGENTS.md` 的构建与验证节
**同一批**）、怎么提改动与反馈。

命令不一致是最常见的坑：CONTRIBUTING 写 `npm test` 而 `AGENTS.md` 写 `node --test`，
两边都不报错，但新来的人会跑错一个。

---

## 六、`LICENSE`

**选哪个只有用户能定。** 给建议时按项目性质：希望被广泛使用 → MIT 或 Apache-2.0；
希望明确专利授权 → Apache-2.0；希望改动必须开源 → GPL 系列（要说清后果）；
不想让别人用 → 不放。

**不要替用户选。** 编一个许可证是替人做法律决定。

落盘规则（硬性）：从 `templates/license-<类型>.txt` 取**逐字**标准文本；只替换年份与版权
持有人；正文一个字符都不改——改过的许可证在法律上可能不成立；清单里的 `license` 字段要
与文件类型一致。年份取系统时间，持有人从清单的 `author` 或提交署名取，读不到就问。

---

## 七、`RELEASING`

要发版时才落。它回答三件事：说明写在哪（默认 `docs/release-notes/<标签>.md`）、
分哪几节（按读者关心的问题定，不套通用模板）、按什么顺序发（说明先提交推送，再打标签，
等自动化，回读确认）。骨架在 `templates/release-notes.md`，是默认菜单。

---

## 八、`.github/` 下的协作模板

要收外部贡献时才落。从 `templates/` 取，不手写——手写会漏要素，而漏掉的要素会让每一份
报告都多一轮追问。落完把占位换成项目真实信息，并删掉模板顶部的说明注释。

---

## 九、项目没有门禁命令时

**交付不能被说成「已验证」。** 一个纯文档项目、一个还没有测试的项目，跑不出什么。
诚实的说法是：

> 这个项目没有可跑的门禁命令，所以这次只验了结构与文档一致性。

判断依据：**你有没有真的跑过一条命令并且看到它通过。** 拿不出实际跑过的输出，
就写「未验证」，这比含糊的「看起来没问题」有用得多。

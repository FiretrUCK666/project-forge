# DeepSeek Harness 插件

## 何时读本文件

- 勘察判定项目是 `dsh-plugin`（清单里声明了 `dsh.bundle`，或存在 `cordis.patch.yml`）时。
- 给一个 DSH 插件配置版本管理、远端或发布链路时。
- 插件加载失败、界面不出现、配置不生效，需要按层排查时。

通用结论（产物入库、两个标识、构建可复现、宿主版本跟随）见
`references/plugin-project.md`，本文件只写这个生态特有的事实。

## 一、怎么认出这类项目

| 证据 | 说明 |
| --- | --- |
| `package.json` 里的 `dsh.bundle` 字段 | 声明「这是一个 DSH 插件，补丁文件在哪」。它是对象里的单个字符串路径（`dsh.bundle.patch`），不是数组 |
| `cordis.patch.yml` | 插件挂载声明：一个行 id 加一个包名 |
| `package.json` 里的 `dsh.client` 字段 | 声明「这个包还有浏览器半区」。有它才有界面，无它只有 host 行为 |
| `package.json` 里的 `dsh.profile` 字段 | 这是 profile 自身的声明（有序 bundle 列表），不是插件作者分发的东西 |

两者通常同时存在。只有配置文件、没有 JS 清单的项目也算这类。

`dsh.client` 展开为 `{ platform, inject?, immediately? }`：`platform` 声明目标界面；`inject` 是包名数组，描述客户端包图边；`immediately` 为可选布尔。`inject` 只描述信息性依赖边，不提供排序、不代替浏览器模块导出的服务名 `inject` 列表。

## 二、四个对象：模块、Bundle、Profile 不要混为一谈

| 对象 | 是什么 | 能否被 `dsh plugin add` 独立激活 |
| --- | --- | --- |
| Host 模块 | 跑在宿主 Node 进程里，经 `ctx` 注册能力的那段代码 | 否 |
| Web 客户端模块 | 跑在浏览器里，经客户端运行时贡献界面或行为的那段代码 | 否 |
| Bundle | 带 `cordis.patch.yml` 的包：插入或覆盖插件行的那一层配置 | 是 |
| Profile | 用户自有的有序组合（目录 + 清单 + 自身补丁），描述一次可运行的组合 | 不是作者分发的东西 |

推论：

- 没有 `dsh.bundle` 声明的包仍能安装，但只作为普通依赖：安装工具会告警且不进层栈。想让人一句话装上，必须交付 Bundle，即使包里只有一个 Host 模块。
- 不要把宿主源码里的内置包目录直接复制出来当可分发插件：它们依赖仓库内的 `workspace:` 图，只能在源码仓库里解析。
- Profile 的清单里有序 `bundles` 列表决定层序；插件作者不分发 Profile，只分发 Bundle。

## 三、两个标识分别是什么

| 标识 | 在哪 | 影响什么 |
| --- | --- | --- |
| **插件 id** | `cordis.patch.yml` 那一行的 `id`（通常与项目目录名一致） | 路由前缀、设置命名空间、存储单元、界面插槽标识、浏览器本地存储键 |
| **包名** | `package.json` 的 `name` | 安装标识；**也是浏览器产物的注册标识** |

**浏览器产物的注册标识必须等于包名，不是插件 id。** 宿主按包清单给产物定键，注册成别的
名字会被拒绝加载（报「loaded without registering `<名字>`」）。没有作用域时两者恰好相同，
一旦加了作用域就会分叉——所以构建配置里写死的注册标识字符串**必须是包名**（以 `package.json` 的 `name` 字段为准）。

**插件 id 派生的一切是数据地址**：路由、设置命名空间、存储键、插槽、本地存储键。加作用域、
换发布者、改包名只动安装标识，这些一个都不许跟着改。改宿主标识是破坏性变更，会让已有
用户的配置与数据失联，真要改必须同时给迁移或明确告知会丢什么。

**发现载体行**：客户端发现按 Loader 行的 `name` 做 `require.resolve('<包名>/package.json')`，
再读该包的 `dsh.client` 声明。因此补丁里必须保留一行 `name` 等于包名自身的行（其 host 入口
可以是空实现）。缺了这一行，包明明装上了，浏览器半区也不会被发现。

自检：构建后检查浏览器产物里注册标识的字符串，与 `package.json` 的 `name` 逐字比对；
并真实执行一次加载握手，而不只是看文件是否存在。自检命令示例：用 `grep` 在构建产物里搜该字符串，确认只出现包名、不出现插件 id。

## 四、宿主加载什么文件

两个半区，各自一个入口，都在 `package.json` 的 `exports` 里声明：

| 半区 | 运行在 | 入口 | 产物 |
| --- | --- | --- | --- |
| host | 宿主的 Node 进程 | `exports["."]` | `lib/index.js` |
| client | 浏览器 | `exports["./client"]` | `lib/client.js`，由宿主在 `/plugins/<包名>/client.js` 提供 |

两半通过包内私有的消息通道通信，只能传无损 JSON。浏览器那一半不能直接读写文件、不能访问
网络——需要这些能力时由它请求 host 半区代做。

**因此 `lib/` 必须进版本库**：安装流程不构建，两个入口指向的文件不存在就是加载失败。
源码与产物必须同一次提交；持续集成里应当重建一次并与提交逐字节比对。

**`--patch` 叠加层只能验证 host 半区**：叠加层按源文件路径挂载，够不到包级的 `dsh.client`
声明。要验证浏览器半区，必须装进 profile（按 `name` 解析），再刷新页面看。

## 五、补丁层语义（最容易写错的一节，先读官方再动手）

`cordis.patch.yml` 是顶层 YAML 数组，每项只有两种操作：

- `insert`（缩进子列表）：向目标分组追加一行以上的新行，按 `id` 定键；
- 按 `id` 整行覆盖（不写 `insert`）：`id` 定位已有的行，可改 `name` / `config` / `disabled` / `inject` / `group` / `isolate` / `intercept`。

三条硬约束：

| 约束 | 说明 |
| --- | --- |
| `config` 是整行替换，不是深合并 | 补丁给的字段就是插件收到的全部，缺的走 schema 默认，不要指望合并 |
| `name` 失配只告警后跳过 | 补丁的 `name` 与目标行对不上时，加载器只告警，该行不生效；`id` 对不上任何行同样只告警 |
| 没有 `replace` / `ignore` 动词 | `insert` 进去的行，后续层仍可按 `id` 再配置或禁用 |

层序（后层覆盖前层，压平成一表后一次性应用）：各 bundle 按 profile 清单列表序 →
profile 自身的 `cordis.patch.yml` → 家目录级补丁（对所有 profile 生效）→ 每次启动的
`--patch` 叠加 → 预设与遥测开关。根 `cordis.yml` 每次启动重写为空表，真实组合树完全由
补丁层组成。

热更新边界：每次启动只有 profile 自身的补丁被持续监听，改它会卸载旧实例并按新组合加载
（读错或解析失败时保住上一次正确树并广播失败事件）。改 bundle 补丁或 `--patch` 叠加
需要重启。

覆盖已有行之前，先看目标组合的当前行：必须把该行需要的键完整重述一遍，不能只写改的那
一个键。

## 六、浏览器产物契约

Web 加载器按经典脚本取回 `lib/client.js`，要求它注册一个懒 CJS 工厂：调用
`window.__ModuleLoader__.load({ id, factory })`，且 `id` 必须等于包名。直接把 ESM 源码拷成
`lib/client.js` 加载不了。

做法：用与目标宿主版本兼容的客户端打包预设产出该工厂形态；若该预设未作为外部可用工具
发布，就 vendored 一份审计过的等价实现，或停下确认该版本支持的外部构建路径。把该辅助
当版本化源码工具对待，不跨版本照搬。

自检：产物里含包名恰好作为工厂 id 且调用了加载器；冒烟时真的按加载器协议执行一遍握手，
而不只是看文件存在。注册 id 与包名不一致、或工厂未注册，表现为界面整体缺席而不是报错
在某一行组件里。

客户端模块表是懒表：副作用只在首次 require 时执行。依赖的客户端运行时与每个注入服务
必须已在目标 Web 组合里挂载，否则浏览器半区起不来。

## 七、界面扩展点与数据归属

插槽是类型化运行时契约，不是 DOM 选择器。动手前在目标版本源码里确认：插槽名、props、
基数、作用域、已有 occupant、所需服务。没有合适插槽时，不要静默替换整页或 patch 私有
DOM；要么提上游插槽需求，要么做明确隔离的新面。

数据走最窄的现成路径，按顺序取：

1. 插槽已给所需数据与动作 → 直接消费 props；
2. 已有客户端服务拥有该数据 → 声明并使用该服务；
3. 持久或特权状态 → 真相放 Host 插件，经目标版本现成的远端模式暴露类型化桥，浏览器只做视图；
4. 浏览器组件只留短暂的呈现态。

界面必须把待定、拒绝、断连、失败的变更显式展示出来。本地乐观更新在 Host 确认前不得报成
持久成功。重连与卸载要测：过期状态、监听器、插槽条目不得在插件卸载后残留。

Host 与客户端之间只传无损 JSON；浏览器侧的持久真相不得绕过 Host 拥有者直接写。

## 八、宿主版本约束

- 依赖包是宿主的一部分，版本不匹配直接表现为加载失败。同步规则见
  `references/plugin-project.md` 第七节与 `references/publish.md`。
- 跟随版本（构建与类型检查所对的版本）必须与实际运行的宿主一致，每次宿主升级都重新对齐。
  发现目标版本时读实际运行的宿主安装目录的清单，不写死安装目录（用解析或包管理器根现场求）。
- 出版方的 `latest` 标记不可信：它可能停在很旧的版本。要取完整版本列表，从末尾找目标版本，
  并逐个包确认该版本确实存在。同一批次里个别包可能停更，不能假定同号普遍成立。
- 最低支持版本是另一回事：只在真不兼容时上移（用了只有新版才有的符号，或在旧版上实测失败），
  且兼容性声明与面向使用者的说明必须一起改。升级后在新版上照常工作，恰恰说明旧下限依然成立，
  此时不要动它。
- 客户端产物能直接引用的模块，是**宿主界面模块表**的镜像：表里有的走外部引用，没有的
  必须内联。这张表与真实宿主不符时会在运行时出错，两个方向都危险（列了已被移除的、
  或少列了新增的）。**每次宿主升级都要重新核对**：在宿主的界面产物里找模块加载器附近的
  种子对象，那份清单就是真值。
- 宿主依赖只从发布版本取，不用源码相对路径；运行时解析必须落到同一份宿主实例上。

## 九、怎么挂载、怎么分发

| | 本地开发 | 正式使用 |
| --- | --- | --- |
| 方式 | 指向本地目录挂载，或用叠加层指向源文件 | 装包：`dsh plugin --profile <profile> add <包名>` |
| 改完生效 | host 半区要重启宿主；client 半区刷新页面即可 | 需要装新版本 |
| 验证 | 叠加层只验 host；完整双面必须装进 profile 再验 | 用隔离 profile 装发布位验证，不用开发链接代替 |

**生效规则要写进面向使用者的文档**：host 半区改动需重启，client 半区刷新页面即可。
本地 `add` 目录是开发链接，仓库目录必须保留在原地；发版验证必须测公开提交位，而不是
本地 checkout。

常用验证：构建与类型与单测 → 入口路径与已提交产物存在 → bundle 在组合转储里作为命名层
出现 → 插入行可解析且 host 模块挂载 → 界面在目标页渲染且交互链路真实走通 → 变更经真实
拥有者往返并能展示拒绝与失败 → 卸载与重载干净释放注册与资源 → 从公开提交位重装一次不依赖
本地目录。

## 十、这个生态特有的坑

- **`files` 白名单对从仓库源安装同样生效**：仓库里有某个文件，不代表使用者手里会有它。
  `lib/`、`cordis.patch.yml`、说明文档都要在范围内。发布前用只打包不发布的手段核对实际文件清单。
- **插件 id 与包名不可互相推导**。加作用域时只动包名，id 与它派生的一切（路由、设置命名
  空间、存储单元、插槽、本地存储键）一个都不许改——那些是用户数据的地址。
- **加载失败就是整个宿主启动失败**，所以版本兼容性是硬约束而不是建议。
- 补丁 `name` 写错只告警不生效：行没起作用时先对 `id` / `name`，不要先怀疑代码。
- 模块层的 `inject` 必须是数组：写成对象会被当成服务名，整树拒绝启动。未声明的服务
  不能防御性直读（会抛错而不是返回空），需要哪个服务就声明哪个，不用的就不要碰。
- `config` 缺字段时走 schema 默认：覆盖行必须重述该行需要的全部键。
- 浏览器半区在叠加层下不可见是正常现象，不是缺陷：要测界面必须走 profile 安装。
- 某设置命名空间在浏览器显示只读或未暴露，多半是宿主网关的显式 allowlist 决策，不是插件
  未注册：这是宿主侧注册通道的问题，插件侧没有开关能加上去。
- 构建把绝对路径交给会写进产物或派生标识的工具（如样式类名哈希取自传入文件名），会让同一份
  源码在不同目录下产出不同字节：构建脚本一律传仓库相对路径。
- 产物内嵌源码原文时，工作区残留的另一套行尾会被原样写进去：先声明文本属性，再按属性重检出后重建。
- 构建号进包有时机要求：先抬号再构建，顺序颠倒会产出旧号包。

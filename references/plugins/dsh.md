# DeepSeek Harness 插件

## 何时读本文件

- 勘察判定项目是 `dsh-plugin`（清单里声明了 `dsh.bundle`，或存在 `cordis.patch.yml`）时。
- 给一个 DSH 插件配置版本管理、远端或发布链路时。

通用结论（产物入库、两个标识、构建可复现、宿主版本跟随）见
`references/plugin-project.md`，本文件只写这个生态特有的事实。

## 一、怎么认出这类项目

| 证据 | 说明 |
| --- | --- |
| `package.json` 里的 `dsh.bundle` 字段 | 声明「这是一个 DSH 插件，补丁文件在哪」 |
| `cordis.patch.yml` | 插件挂载声明：一个行 id 加一个包名 |

两者通常同时存在。只有配置文件、没有 JS 清单的项目也算这类。

## 二、两个标识分别是什么

| 标识 | 在哪 | 影响什么 |
| --- | --- | --- |
| **插件 id** | `cordis.patch.yml` 那一行的 `id`（通常与项目目录名一致） | 路由前缀、设置命名空间、存储单元、界面插槽标识、浏览器本地存储键 |
| **包名** | `package.json` 的 `name` | 安装标识；**也是浏览器产物的注册标识** |

**浏览器产物的注册标识必须等于包名，不是插件 id。** 宿主按包清单给产物定键，注册成别的
名字会被拒绝加载（报「loaded without registering `<名字>`」）。没有作用域时两者恰好相同，
一旦加了作用域就会分叉——所以构建配置里写死的那两个字符串**必须是包名**。

自检：构建后检查浏览器产物里注册标识的字符串，与 `package.json` 的 `name` 逐字比对；
并真实执行一次加载握手，而不只是看文件是否存在。

## 三、宿主加载什么文件

两个半区，各自一个入口，都在 `package.json` 的 `exports` 里声明：

| 半区 | 运行在 | 入口 | 产物 |
| --- | --- | --- | --- |
| host | 宿主的 Node 进程 | `exports["."]` | `lib/index.js` |
| client | 浏览器 | `exports["./client"]` | `lib/client.js`，由宿主在 `/plugins/<包名>/client.js` 提供 |

两半通过包内私有的消息通道通信，只能传无损 JSON。浏览器那一半不能直接读写文件、不能访问
网络——需要这些能力时由它请求 host 半区代做。

**因此 `lib/` 必须进版本库**：安装流程不构建，两个入口指向的文件不存在就是加载失败。

## 四、宿主版本约束

- 依赖包是宿主的一部分，版本不匹配直接表现为加载失败。同步规则见
  `references/plugin-project.md` 第七节与 `references/publish.md`。
- 客户端产物能直接引用的模块，是**宿主界面模块表**的镜像：表里有的走外部引用，没有的
  必须内联。这张表与真实宿主不符时会在运行时出错，两个方向都危险（列了已被移除的、
  或少列了新增的）。**每次宿主升级都要重新核对**：在宿主的界面产物里找模块加载器附近的
  种子对象，那份清单就是真值。

## 五、怎么挂载、怎么分发

| | 本地开发 | 正式使用 |
| --- | --- | --- |
| 方式 | 指向本地目录挂载 | 装包：`dsh plugin --profile <profile> add <包名>` |
| 改完生效 | host 半区要重启宿主；client 半区刷新页面即可 | 需要装新版本 |

**生效规则要写进面向使用者的文档**：host 半区改动需重启，client 半区刷新页面即可。

## 六、这个生态特有的坑

- **`files` 白名单对从仓库源安装同样生效**：仓库里有某个文件，不代表使用者手里会有它。
  `lib/`、`cordis.patch.yml`、说明文档都要在范围内。
- **插件 id 与包名不可互相推导**。加作用域时只动包名，id 与它派生的一切（路由、设置命名
  空间、存储单元、插槽、本地存储键）一个都不许改——那些是用户数据的地址。
- **加载失败就是整个宿主启动失败**，所以版本兼容性是硬约束而不是建议。

## 事实来源

本文件的事实来自在本机对宿主实现的实际核对：技能与插件加载器的根目录解析、包清单到
浏览器产物的定键过程、以及宿主组合层对 `dsh.bundle` 的读取。核对方式为读取宿主安装目录
下对应包的实现代码。这些事实随宿主版本可能变化——**升级宿主后应重新核对第二节与第三节**。

# Go 专章

> 发布总纲见 `references/publish.md`（版本语义、发布通道的取舍、“发布”这个动作的一般模型）。本文件只讲 Go 这一条通道，不重复总纲内容。**不要把 npm 那套“上传一个包”的模型套到 Go 上**，两者根本不同。

## 何时读本文件

出现下列任一情况时读全文：

- 用户说发版、发个版本、让别人能 `go get` 到；
- 需要定版本号、打标签、处理多模块或大版本升级；
- 下游报版本找不到、校验失败、拉到旧代码，要找原因；
- 需要撤回坏版本（retract）或处理私有模块。

读完后应能独立回答：该打什么标签、推到哪、怎么确认收录、坏了怎么往前修。

## 一句话模型：没有上传动作

Go 的“发布”就是**打一个版本标签并推送**，由模块代理按需从源码仓库拉取并缓存：

```sh
go mod tidy
go test ./...
git tag v0.1.0
git push origin v0.1.0
```

再显式触发一次代理收录（约一分钟可用），下游即可按版本号获取。**没有登录、没有上传、没有等待收录的按钮。**

## 标签形状：三条硬规则

版本号必须以 `v` 开头，后跟语义化版本（三段数字，可选预发布后缀与构建元数据）：

| 情形 | 标签怎么写 |
| --- | --- |
| 单模块仓库 | `vX.Y.Z`（如 `v1.2.3`） |
| 子目录里的模块 | 加子目录前缀（如模块在 `module1/` 下，标签为 `module1/v1.2.3`）；引用时仍写模块路径加版本号 |
| 大版本升级（v2 起） | 模块路径必须同步加 `/v2` 后缀（如 `example.com/mod/v2`），并改 `go.mod` 的 module 路径与全部导入路径；升级大版本本质是发布一个新模块 |

伪版本（无标签提交自动生成的带时间与 commit 前缀的版本）由工具生成，**不要手写**。标签轻重（annotated 还是 lightweight）官方未明示要求，不编造额外规矩。

## 预发布：默认不被选中

`-` 后缀标识预发布里程碑（如 `v1.2.3-alpha`），排在对应正式版之前，无稳定性保证。`go` 命令默认偏好正式版，预发布必须显式按完整版本号获取。不要拿预发布当正式对外。

## 确认收录：延迟是正常的

- 刚推送就查不到，多半是代理缓存：显式请求一次该版本后等待回读，不要立刻重发或换号。
- 若在打标签前有人请求过该路径，旧缓存最长保留一段时间才过期，同样等，不要用改号硬撞。
- 确认方式是按版本拉取成功，不是看命令退出码。

## 已发布不可改：只能向前

- **不要改已发布标签指向的代码**：工具按首次下载副本做认证，不一致报安全错误；正确做法永远是发新版本。
- 坏版本用 retract 声明撤回：在 `go.mod` 里加 `retract` 指令说明版本区间与原因，**再发一个更高新版**让它生效。retract 版仍保留可用（不断已依赖构建），但不再被自动选中，版本列表默认隐藏它。
- 删标签、删仓库不能让代理忘记已缓存的内容，正确做法仍是发新版加劝用。

## 最低 Go 版本：`go` 指令是强制线

`go.mod` 的 `go` 指令声明使用该模块所需的最低 Go 版本：新版工具链强制执行，旧版按行为开关回退。**只在真不兼容时上移**（用了只有新版才有的语言特性，或在旧版实测失败），并同步面向使用者的说明。上移门槛只会挡住本可使用的人。

## 私有模块：靠仓库可见性隔离

代理与校验服务只服务公开代码。依赖私有模块时，用模块路径匹配把私有范围排除在代理与校验之外、走直连；彻底一点可指定直连。私有模块发版同样是打标签，**仓库私有则模块不可被外部取到**——分发范围与仓库可见性绑定，没有白名单筛选这一层。

## 常见翻车对照

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 下游报校验失败 | 重打了同号标签，代码与首次副本不一致 | 废弃该号，发新版；检查 `go.sum` 只许经命令改 |
| 打了标签代理找不到 | 子目录漏前缀，或大版本漏 `/v2` | 按三条硬规则重打正确形状的标签 |
| 预发布发了没人拿到 | 预发布默认不选中 | 明确告知下游显式按版本号获取 |
| 改了仓库名老导入全坏 | 模块路径即导入地址 | 改名等于换模块名，提前说明并做迁移期 |

# Python 专章

> 发布总纲见 `references/publish.md`（版本语义、发布通道的取舍、“发布”这个动作的一般模型）。本文件只讲 Python 这一条通道，不重复总纲内容。

## 何时读本文件

出现下列任一情况时读全文：

- 用户提到发到 PyPI、发包、传包，或要求“把这个 Python 项目发出去”；
- 项目里已有 `pyproject.toml`，需要判断发布相关字段缺什么；
- 需要配置或排查自动发布（可信发布、API Token）、预演或 TestPyPI；
- 发布报错（文件名已存在、渲染失败、无权），要找修正路径。

读完后应能独立回答：这个包能不能发、缺哪几步、走哪条认证、发前验什么。

## 清单：三个表各管什么

权威来源是 `pyproject.toml`，分三个表，不要混为一谈：

| 表 | 管什么 | 要点 |
| --- | --- | --- |
| `[build-system]` | 用哪个后端构建 | 必须有：`requires` 含后端包，`build-backend` 指明后端（如 hatchling、setuptools、flit 系，按后端文档抄）。缺了它，前端只能回退到旧行为 |
| `[project]` | 包的身份与元数据 | `name` 必填且唯一（只许 ASCII 字母数字 `_-.\`，首尾禁 `_-.\`，比较大小写不敏感）；`version` 必填，但常写 `dynamic` 交后端从源码或标签填充；`requires-python` 是支持下限（安装器会向前回溯找匹配旧版）；`license` 写 SPDX 表达式并配 `license-files` |
| `[tool.*]` | 各工具专属配置 | 后端与测试、检查工具各自认自己的节，不要跨节套用 |

`setup.py` 只在编程式配置（如 C 扩展）确需时保留，新项目默认不用。包名被占用只能换名，没有后缀可加。

### 字段现形记：最容易写错的五处

勘察的 `pythonMeta` 只报有无，语义在这里一次讲透：

- **`license` 是 SPDX 字符串，不是旧字典写法**：新后端要求 `license = "MIT"` 这类
  表达式并配 `license-files` 收许可证文本；旧的 `{file=...}` / `{text=...}` 写法
  在新后端下会报类型错误。判据：看构建后端的最低版本要求，按后端文档抄，不要凭记忆混写。
- **`readme` 决定长描述能不能渲染**：缺了它或路径写错，`twine check` 即失败，
  服务端以长描述渲染失败直接拒绝。未知后缀必须显式声明内容类型。
- **`requires-python` 是唯一真正约束安装的下限**：分类标签里的 Python 版本只管
  搜索展示，不管安装。缺了它，用户装到旧版时难定位——`review` 只报待问，不挡发布。
- **`name` 禁止 `dynamic`**：静态与动态同列一字段即报错；`dynamic` 声明了但后端
  给不出值同样报错；后端不许自作主张填未声明的值。
- **`version` 常走 `dynamic`**：由后端从源码常量、文件或标签填充（各后端在 `[tool.*]`
  接线不同，`[project]` 侧统一都是 `dynamic = ["version"]`）。
  此时 tag 对齐按后端的取值，不要照抄文件里的字面版本号。

## 构建：先产出确切文件，再谈发布

顺序固定：构建 → 预演 → 上传，缺一步都不发。

```sh
python -m build        # 产出 dist/*.tar.gz（sdist）与 dist/*.whl（wheel）
twine check dist/*     # 长描述渲染校验，--strict 则警告即失败
```

- sdist 必须传（`.tar.gz`，含 `pyproject.toml` 与包元数据）；wheel 按兼容平台提供，纯 Python 常只有一个。
- 构建前端（`build`）与上传工具（`twine`）是两个东西：`twine` 的价值就是“先构建好确切文件再传”，不要用一边构建一边传的老路（传出去的东西没验过）。

## 预演：TestPyPI 是独立世界

TestPyPI（`test.pypi.org`）与正式 PyPI 账号、Token、存储完全隔离，定期清理不永久保存：

1. 在 TestPyPI 单独注册并建 Token；
2. 传测试包：`twine upload --repository testpypi dist/*`；
3. 在隔离干净环境按真实安装路径装一次，确认能装、能引用。

从测试源装依赖时注意用正式源补依赖，不要从测试源误装依赖。预演通过不代表正式自动通过，两边各验各的。

## 认证：首选可信发布，次选 API Token

| 方式 | 怎么工作 | 前提 |
| --- | --- | --- |
| 可信发布（OIDC） | CI 提交短期身份，PyPI 匹配受信配置后铸造仅 15 分钟有效的项目级 Token | 在 PyPI 上为该包建 pending publisher（包名、仓库、workflow 文件名逐字一致，另有 environment 名）；job 声明短时身份签发权限；构建与发布分 job（不支持在发布 job 内构建）；旧的长期 Token 删掉并吊销 |
| API Token | 长期有效的密钥 | 用户名固定填 `__token__`，口令填 Token；放 CI 机密存储或 `~/.pypirc`（该文件权限收紧）；[TestPyPI 与正式各用各的 Token |

账号本身必须开双因素；加删协作者、删分发、建 Token 等敏感操作需一小时内确认密码。可信发布配好后，发布记录能追溯到具体构建；长期 Token 泄漏即轮换，没有“先凑合用”的中间态。

### 可信发布接线步骤（带着用户在浏览器里填）

登记动作只能由账号持有人在制品库网站上做，AI 碰不了——但 AI 要把每一项要填什么讲清楚，
否则用户面对表单只能猜。路径：包页面（新包用账号页的发布者管理入口建 pending publisher）
→ 受信发布配置：

| 项 | 填什么 | 填错的后果 |
| --- | --- | --- |
| 包名 | 与 `pyproject.toml` 的 `name` 逐字一致 | 大小写都敏感，错一个字符即无权 |
| 仓库 | 源码仓库的拥有者与仓库名 | 同上 |
| 工作流文件名 | 仅文件名（如 `release.yml`），且该文件必须真实存在于仓库 `.github/workflows/` 下 | 不存在即无权 |
| Environment 名 | 与工作流里发布 job 的 `environment:` 逐字一致（常用正式 `pypi`、测试 `testpypi`） | 不一致即无权 |

四条必须提前说的现实：

- 制品库保存时**不校验**这几项，填错只在发布那一刻爆错，且错误信息不区分“无权”与“目标不存在”
  （常被误判成包名写错）——对照工作流文件与包名逐字核对，而不是重填碰运气；
- 工作流里发布 job 要声明短时身份签发权限（`id-token: write`），且**构建与发布必须分 job**：
  发布 job 只下载构建产物再上传，不在发布 job 内构建；
- 正式与测试是两个独立世界：pending publisher、Token、存储**各建各的**，
  测试的接线里发布地址要指测试源；
- 接线验证不用真发一版：手动触发一次该工作流，若卡在“文件名已存在”而不是认证失败，
  说明线是通的。切到可信发布后删掉旧的长期 Token。

## 版本与修正：删不掉，只能向前

- 版本遵循版本规范：公开版为数字段加可选预发布（`a/b/rc`）、`post`、`dev` 后缀；排序是 `dev < a < b < rc < 正式 < post`；PyPI 禁止本地版本号（`+` 后缀，含它传不上去）。
- 预发布默认不被安装器选中，除非显式请求；不要拿预发布当正式版发。
- **已用文件名永不复用**：分发文件名由包名 + 版本 + 分发类型三者决定，用过即烧号——
  同名同版本同类型传过一次，再传（哪怕删过）也报已存在，删项目重建同名也救不回来。
  这是防“同一坐标某天被偷换”的供应链铁律。对策永远是**改版本号重建重传**。
  `--skip-existing` 只跳过已存在文件，会掩盖“以为发出去了实际没更新”，不得当常规重试手段
  （只在测试源排查时考虑，正式源让它大声失败）。
- 修正路径只有向前：发新版本。发坏的版本用 yank 标记（安装器默认忽略，显式 pin 仍可装，
  存量锁文件不炸；可附理由、可撤销），不要删除——删除永久不可逆，删项目名还会被他人占用。
  **只 yank 不 delete**。
- 制品里混入凭据：先吊销凭据再发新版；旧下载收不回，yank 拦不住已扩散的副本。
  制品库会自动扫描公网泄露的令牌并先行吊销，收到吊销通知先查原因；全员开双因素。

## 私有分发

PyPI 不支持私有包。只给内部用时自建索引服务，发布目标与认证按该服务的文档来，不要把内包传到公共 PyPI“先占个名”。

消费侧按私有源配置安装来源（主源整个换掉，或正式为主、私服为辅），自签或 HTTP 源才需加信任主机。
安全忠告：双源是“版本号高者胜”，私包名若与公网撞名会被公网高版本劫持——私包尽量用独特前缀名，
主源切私服，并用哈希锁定。注定不公开的包可加防误传分类让公共源永远拒收。

## 常见翻车对照

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| 报文件名已存在 | 同号重传（删过也一样） | 改版本号重建重传 |
| 长描述渲染失败被拒 | `twine check` 没跑 | 跑预演修好再传 |
| 无权 | Token 与目标源不匹配（拿测试源 Token 传正式源）或可信发布登记项差一个字符 | 逐字核对登记项与目标地址 |
| 刚传完查不到 | 收录延迟 | 等一会儿再查，不要重传撞占用 |
| 传完用户装到旧版 | `requires-python` 把新用户挡在旧版 | 检查下限声明是否真有必要上移（见总纲跟随与下限） |

## 提问与反馈

遇到问题、想要新能力、发现文档不清楚，都请到项目的 Issue 区提出。

为了让问题能被定位，请一并附上：

- 你使用的版本
- 你的运行环境（操作系统、相关运行时的版本）
- **完整的报错文本**（不要只描述现象，也不要只截一行）
- 最小复现步骤（如果问题能稳定重现）

请先搜索已有的 Issue，避免重复。

## 报告缺陷

一个可用的缺陷报告包含四件事：期望发生什么、实际发生什么、怎么复现、在什么环境上。

如果问题只在特定条件下出现，把那个条件写出来——它往往就是根因所在。

## 提出改动

1. 先开一个 Issue 说明你想改什么、为什么。涉及行为变化或新增依赖的，先在 Issue 里
   讨论清楚再动手，避免写完才发现方向不对。
2. 从主干拉出自己的分支，在上面开发。
3. 跑完提交前门禁（见下），全绿再提交。
4. 提交拉取请求，说明改了什么、为什么、怎么验证的。

**请只推自己的分支，不要推主干，也不要打版本标签或发布制品**——那些由维护者执行。

## 开发环境

列出如何把项目跑起来、如何运行测试。命令要具体。

```sh
# 获取代码
# 安装依赖
# 运行测试
```

## 提交前门禁

改完必须全绿才算完成。按顺序：

```sh
# 构建
# 静态检查
# 测试
# 自检
```

如果项目把生成产物提交进了版本库，改完源码后必须**重新构建并一起提交**——否则产物
与源码会脱节。

## 硬性规范

从项目的 `AGENTS.md` 里摘出对贡献者同样成立的几条（例如：禁止 emoji、命名一致性、
不新增依赖、数据键不得改名）。**完整规范以 `AGENTS.md` 为准**，这里只列最关键的部分，
不要重复维护一份。

## 提交信息

一句话说明这次改了什么。中文或英文都可以，但**不要使用 emoji**。一次实质改动一个
提交，不要把无关改动混在一起。

## 许可

提交贡献即表示你同意以本项目的许可证发布你的贡献（见 `LICENSE`）。

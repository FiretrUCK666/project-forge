## 独立审查与故障注入

<!-- 触碰高风险路径时必填，其余情况写「未触碰高风险路径，不适用」。四项都要有且保持在同一连续段内： -->

- **审查来源**：这一轮审查来自哪个独立上下文（子代理 / 新会话 / 另一个人）。它与执行者不是同一个
  上下文；只给它目标、冻结的验收标准、diff 与门禁原始输出，**不给执行者的思路与上一轮结论**。
- **逐条标准状态**：按 `fail: C1, C4` / `pass: C2, C3` 写，**一轮一行**，行首标出第几轮、当轮的
  HEAD 短哈希，以及**被审那份 diff 的哈希与字节数**。哈希要用一条谁跑都一样的取法：
  `git diff <基线>...<HEAD> > d.txt`，再对 d.txt 求 sha256（**中间不要经过任何会改行尾或编码的
  工具**，那会得到一个别人算不出来的值，等于结论没绑住任何东西）。审查者自己跑一遍，对不上
  就是这一条没过。不写「整体不错」这类评价——它既不是 fail 也不是 pass。
  **「通过」不是一句话，是 `fail` 为空加下面那份注入记录。**
- **故障注入记录**：「删掉一行核心代码，确认测试变红；还原后，确认变绿」的实际输出。
  测试全绿有两种可能——代码对了，或者测试是空的；只有看到它红过，才排除后一种。
- **止损记录**：触发过哪条止损（同一条标准连续两轮没过 / 轮次超上限 3 轮），以及把什么交回了人。
  没触发就写「未触发」。

<!--
审查方守收敛边界：第 1 轮看全量并一次指出同类全部问题；第 2 轮只复核未闭环 Must Fix 与增量修复；第 3 轮只对增量行做 Pass/Fail。打回后在原分支追加提交、更新同一个 PR；HEAD 没前进的重提拒绝。
-->
